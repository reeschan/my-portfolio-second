# 0002. フレームワークとホスティング: Next.js (App Router) + Vercel

- 状態: 採用 (後付け)
- 日付: 2026-10-06 (決定自体は 2025 年のサイト立ち上げ時)
- 関連: PBI-0001

## 背景

個人のポートフォリオを、少ない運用の手間で公開したい。ページは静的な内容が中心だが、職務経歴について答える AI チャット (`/api/chat`) と RSS (`/rss.xml`) のようにサーバー側の処理も要る。
チャットの資料 (職務経歴書など) はブラウザに配らず、サーバー側だけで読みたい。

> この ADR は、すでに採用していた選択を後から記録したもの。

## 決定

- **Next.js の App Router** で作る。ページは `app/<ルート>/page.tsx`、API は `app/api/<名前>/route.ts`
- 既定はサーバーコンポーネント。操作や three.js が要る部品だけ `"use client"` にする
- **Vercel** にデプロイする。チャット API は Node.js ランタイムで動かし、`maxDuration` は Hobby プランの上限 (60 秒) に合わせる
- パッケージマネージャは **pnpm**、言語は **TypeScript (strict)**

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| Next.js + Vercel (採用) | ページと API を 1 つのリポジトリで書ける。サーバー側だけで資料を読める。デプロイが push だけで済む | フレームワークの破壊的変更が多い (AGENTS.md の冒頭の注意) |
| Astro / 静的サイト + 別の API | 静的部分は軽い | チャット API を別に運用する手間が増える |
| Vite + React (SPA) | 構成が単純 | 資料をサーバー側だけで扱うには別にサーバーが要る |

## 結果

- サーバー側の資料の読み込み (`lib/chat/system-prompt.ts`) と、ブラウザ側の部品をはっきり分けられる
- Next.js のメジャー更新では、`node_modules/next/dist/docs/` を読んでから直す (AGENTS.md)
- 本番ビルドは Google Fonts を取りに行くため、ネットワークを制限した環境ではビルドできない (0001 の結果を参照)
- 資料の置き場所は ADR 0019 で data/ から Vercel Blob (private) に移した
