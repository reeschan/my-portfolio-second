# 0003. UI の基盤: Tailwind CSS v4 + shadcn/ui (Radix) + lucide + Motion

- 状態: 採用 (後付け)
- 日付: 2026-10-06 (決定自体はサイト立ち上げ時。v0 の生成物を引き継いだ)
- 関連: PBI-0001、0004、0005

## 背景

サイトは v0 で生成した画面から始まった。生成物は Tailwind と shadcn/ui の部品で書かれている。
これを捨てずに育てるか、別の UI 基盤に移るかを決める必要があった。

> この ADR は、すでに採用していた選択を後から記録したもの。Tailwind は v4 (CSS ファースト設定) に移行済み。

## 決定

- **Tailwind CSS v4** を使う。設定は `tailwind.config` ではなく `app/globals.css` の `@theme` に書く
- 基本部品は **shadcn/ui** (中身は Radix UI) を `components/ui/` にコピーして持つ。依存ではなく自分のコードとして直してよい
  - ダイアログ・タブなどのアクセシビリティ (フォーカス管理・キーボード操作・ARIA) は Radix に任せる
- アイコンは **lucide-react**、アニメーションは **motion** (旧 framer-motion)
- クラスの結合は `cn()` (`clsx` + `tailwind-merge`)、部品の見た目の種類は `class-variance-authority` (cva) で表す

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| Tailwind + shadcn/ui (採用) | v0 の生成物をそのまま使える。部品が手元にあるので直しやすい。Radix で a11y の土台がある | クラスが長くなりがち (→ 0005 で部品に閉じ込める) |
| CSS Modules + 自作部品 | 依存が少ない | ダイアログなどの a11y を自前で作る必要がある |
| MUI などの完成品の部品集 | すぐ使える | ガラス調の独自の見た目に寄せにくい。バンドルが重い |

## 結果

- 見た目の約束事はトークン (0004) と部品 (0005) に寄せ、画面では生の色やクラスの組み合わせを増やさない
- shadcn/ui の部品を直したら、その部品を使う画面の E2E が通ることで確かめる
