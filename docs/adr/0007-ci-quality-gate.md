# 0007. CI の品質ゲート: lint・型・ユニット・ビルド・E2E が通らないとマージできない

- 状態: 採用
- 日付: 2026-10-06
- 関連: PBI-0001、0001、0009

## 背景

CI (型・ユニット・E2E) はあったが、lint がなく、ブランチ保護もないため、CI が落ちていてもマージできた。
エージェントに PR を任せる以上、「CI が緑でなければマージできない」ことを仕組みで保証したい。

## 決定

1. **ESLint** を入れる (`eslint.config.mjs`、Next.js の `core-web-vitals` + `typescript`)
   - Next.js 16 で `next lint` がなくなったため、ESLint CLI を直接使う
   - **ESLint は 9 系に固定**する。10 系は eslint-plugin-react (eslint-config-next が使う) と互換がなく、起動時に落ちるため。plugin が対応したら上げる
2. CI (`.github/workflows/test.yml`) のジョブを分ける: `lint` / `typecheck` / `unit` / `build` / `e2e`
   - `e2e` は `build` の成果物 (`.next`) を受け取って本番ビルドに対して回す
   - E2E の前に `pnpm test:coverage-map -- --check` で必須観点の穴を検出する
3. 最後に **`ci-ok`** ジョブを置き、全ジョブの成功を確かめる。**ブランチ保護で必須にするのは `ci-ok` だけ**
   - ジョブを足しても `needs` に足すだけでよく、ルールセットを直さなくてよい
   - 失敗・中断・スキップのどれでも `ci-ok` は落ちる
4. ブランチ保護は **ルールセット** (`.github/rulesets/main.json`) で定義する: 既定ブランチへの PR 必須・`ci-ok` 必須・削除と force push の禁止
   - ルールセットの適用はリポジトリの管理者が GitHub の画面で取り込む (Settings → Rules → Rulesets → Import a ruleset)。ファイルを置いただけでは効かない

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| ジョブを分けて `ci-ok` だけ必須 (採用) | どこで落ちたかが一目で分かる。必須チェックの管理が 1 つで済む | ジョブごとに依存のインストールが走る |
| 1 ジョブで全部 | 速い | どこで落ちたかが分かりにくい |
| 各ジョブを個別に必須にする | ルールセットだけで完結する | ジョブ名を変えるたびにルールセットも直す必要があり、直し忘れると素通りになる |

## 結果

- 手元では `pnpm check` (lint・型・ユニット・ビルド) と `pnpm test:e2e` で CI と同じ確認ができる
- コミット前の検査 (0009) と同じ項目を CI でももう一度確かめる二段構えになる
- PR で E2E を回すのは ADR 0022 でやめた (E2E は develop へのマージ後に回す)
