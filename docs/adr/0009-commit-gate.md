# 0009. コミットゲート: E2E の追加と全テストの合格をコミットの条件にする

- 状態: 採用
- 日付: 2026-10-06
- 関連: PBI-0001、0007、[.claude/skills/commit-gate/SKILL.md](../../.claude/skills/commit-gate/SKILL.md)

## 背景

CI で止めるだけでは、テストを足さずに機能を変えたコミットや、落ちるコミットが積み上がってから気づくことになる。
特にエージェントは「実装したがテストは後で」となりやすい。コミットの時点で、変えた機能に E2E が付いていて、全部通ることを確かめたい。

## 決定

1. 検査の本体は `scripts/commit-gate.mjs` (`pnpm commit-gate`)
   - 画面のコード (`app/` のページ、`components/`) を変えたら `e2e/*.spec.ts` がステージされていること
   - 処理のコード (`lib/` `hooks/` `app/api/`) だけなら E2E かユニットのどちらか
   - `data/` だけ、ドキュメントだけの変更は不要
   - そのうえで lint / 型 / ユニット / 必須観点の穴 / E2E を全部回す
   - 振る舞いを変えないリファクタは `--waive "理由"` で E2E の追加だけを免除できる (検査は全部回る)
2. 合格したら、**ステージ内容のツリー ID** (`git write-tree`) を `.git/commit-gate.json` に記録する
   - 検査のあとにステージ内容が変われば ID が変わり、合格は無効になる
3. Claude Code の **PreToolUse フック** (`.claude/hooks/commit-gate.mjs`) が `git commit` を見張り、記録と一致しなければ止める
   - 引用符の中やヒアドキュメントの「git commit」という文字は対象にしない (判定は `scripts/commit-gate-match.mjs`、テストあり)
4. 手順は **`commit-gate` スキル**にまとめる。フックに止められたときもスキルの手順に戻る
5. 人のコミットにも同じ検査をかけたい場合は `git config core.hooksPath .githooks` で有効にする (任意)

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| スキル + 合格の記録 + フックで確かめる (採用) | フックは記録を見るだけなので速い。検査とコミットの間のすり替えも検出できる | 「add → 検査 → commit」を別々に打つ必要がある |
| フックの中で毎回全テストを回す | 手順が 1 つで済む | コミットのたびに数分かかり、フックの時間制限に当たる |
| husky などで git フックだけ | 人にもエージェントにも効く | 全員の手元に強制すると、ドキュメントの修正にも重い検査がかかる |

## 結果

- エージェントのコミットは、E2E の追加と全テストの合格が前提になる
- 最後の砦は CI の `ci-ok` (0007)。手元の検査を飛ばしても (`--no-verify` など) マージはできない
