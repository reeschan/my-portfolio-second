# 0012. 3D 背景のテーマ: 選べるシーンをテーマごとのファイルに分け、色はシーンが持つ

- 状態: 採用
- 日付: 2026-10-08
- 関連: PBI-0002、0004、0006

## 背景

3D 背景は 1 種類 (浮遊する多面体とグリッド) だけだった。夜・自然・月をモチーフにした写実的なシーンを複数用意し、閲覧者が `/theme` で選べるようにしたい。
これに伴い、次のことを決める必要がある。

- 複数のシーンをどう分け、どう読み込むか (three.js のシェーダーは大きく、全テーマを最初に読ませたくない)
- 選んだテーマをどこに保存し、全ページの背景とどう共有するか
- シーンの配色をどこで管理するか (0004 は「生の色を書かない、three.js には lib/theme.ts から渡す」と決めている)

## 決定

- テーマは `components/features/background/themes/<id>.tsx` に 1 ファイルずつ置き、`<Canvas>` の中身だけを書く
  - `scene.tsx` が `React.lazy` で選ばれたテーマだけを読み込む。テーマを替えたら `key` で Canvas ごと作り直す
  - 外部のテクスチャ・モデルは使わず、シェーダーと生成したジオメトリだけで描く (ネットワークとライセンスの心配をなくす)
- テーマの一覧 (id・表示名・説明・見本の色) と選択中のテーマのストアは `lib/background-theme.ts` に置く
  - `/theme` の部品 (`features/theme`) と背景 (`features/background`) は互いを import しない (0005)。共有するものは lib に置く
  - 選択は `localStorage` に保存し、`useSyncExternalStore` で購読する。サーバー描画とハイドレーション中は既定のテーマ
- **シーンの配色はテーマのファイルが持つ** (0004 の例外)
  - 写実的なシーンは空・月・霧などに数十の色を使い、サイトの UI トークンとは役割が違う。トークンに上げても再利用されない
  - UI に出る色 (テーマ一覧の見本のグラデーション) だけは `lib/background-theme.ts` に定数でまとめる
  - 既定の「グリッド」テーマは従来どおり `lib/theme.ts` の `sceneColors` を使う (2026-10-23 から既定はガラス。結果の節の追記)
- シーンは「本文パネルの裏 (画面中央) を暗めに保つ」「主役の光源 (月・コロナなど) は上か端に置く」を守り、ガラス調パネルの文字を読みやすく保つ
- 制作はサブエージェント (並列で候補を作り、テーマごとに 1 つ選んで 10 回の校正) で行った。経過は PBI-0002 の WORK に残す

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| テーマごとのファイル + lazy 読み込み (採用) | 選ばれたテーマのコードだけを読む。テーマを足すのがファイル 1 つで済む | テーマ間で共通のシェーダー部品 (ノイズ関数など) が重複する |
| 1 つのシーンをパラメータで切り替える | コードが少ない | 月面と森のように構図がまったく違うシーンを表せない |
| 動画や画像を背景に流す | 写実性は最も高い | 重い。マウスへの追従や奥行きが出せない。素材のライセンスが要る |
| next-themes の theme に相乗りする | 保存の仕組みを書かなくてよい | ライト/ダーク (UI の色) と背景のシーンは独立した選択なので混ぜたくない |

## 結果

- テーマのファイルには生の色 (`#0b1020` や GLSL の `vec3(...)`) が書かれる。UI のコード (`app/`、`components/` の DOM) では引き続きトークンだけを使う
- E2E (`e2e/background-theme.spec.ts`) は描画結果のピクセルを比べず、canvas の `data-background-theme` と、全テーマがエラー (シェーダーのコンパイル失敗など) なく描けることを確かめる
- シェーダーは端末の GPU に負荷をかけるので、dpr の上限を 1.75 に下げた
- 2026-10-21 追記 ([PBI-0025](../pbi/0025-render-load/PBI.md)): 見た目をほぼ変えずに描画の負荷を削るため、次を決めた
  - 30fps に間引く。Canvas を `frameloop="never"` にし、requestAnimationFrame の中で間隔を測って `advance` を呼ぶ。背景は動きがゆるやかなので、30fps でも見た目はほぼ変わらない
  - `antialias` は切る。`powerPreference` は付けず既定に任せる (ノート PC で外付けの GPU を起こさない)
  - dpr は範囲 `[1, 状態]` で渡し、端末の画素密度を 1〜1.75 に抑える。数値で渡すと端末に関係なくその倍率で描くため
  - 24fps を下回ったら dpr を 1 に下げる (drei の `PerformanceMonitor`、bounds は `[24, Infinity]`)。drei の既定の bounds は 40〜60fps で、30fps に間引くと常に「重い」と判定されるため
  - `prefers-reduced-motion: reduce` では `frameloop="demand"` にし、止まった 1 枚だけを描く。間引きと PerformanceMonitor は使わない
  - 定数 (fps・dpr の上限と下限・下げる閾値) と間引きの判定は `lib/background-frame.ts` に置く
  - 新しいテーマは時間の経過 (`delta` / `clock.elapsedTime`) で動かし、フレームの数で動かさない。30fps に間引いても動く速さを保つため
- 2026-10-23 追記 ([ADR 0034](0034-intro-and-background-handoff.md)): 3D 背景の読み込みの時刻 (全ページでブラウザの手が空いてから) と、「背景の準備完了」の知らせ、トップの導入演出からの引き継ぎは ADR 0034 で決めた
- 2026-10-23 追記 ([PBI-0030](../pbi/0030-glass-theme/PBI.md)):
  - テーマ「ガラス」を足し、一覧の先頭に置いて既定のテーマにした。導入演出 (ADR 0034) と同じ紫のガラスの世界観で、引き継ぎで見た目が急に変わらないようにするため。保存済みの選択は今までどおり優先する
  - 全画面 1 枚のシェーダーで描き、すべての動きを 10 秒で 1 周する位相の関数にして、つなぎ目なくループさせる (位置・回転・明滅は位相の整数倍の sin・cos、ノイズは場を位相の円の上で動かす、塵は場を流さず各粒がセルの中で円を描く)。シェーダーに渡す時刻は経過時間をループの長さで割った余りにする (`lib/background-frame.ts` の `loopTime`)
  - 色は導入演出のトークンの値を `lib/theme.ts` の `introColors` から渡す。three.js の `Color` は線形に変換されるので、sRGB の値のまま渡す
  - 動画ファイルは使わない (シェーダーなら数 KB で、30fps の間引き・解像度の自動調整・視差効果を減らす設定がそのまま効くため)
  - 仕様は [docs/specs/glass-theme-and-navigation.md](../specs/glass-theme-and-navigation.md)
- 2026-10-23 追記 ([PBI-0030](../pbi/0030-glass-theme/PBI.md)):
  - 既定のガラスは全画面のシェーダーで重く、GPU の無い環境 (E2E のソフトウェア描画) ではページの移動が 15 秒を超えた
  - 対処として dpr の段を 1.75 → 1 → 0.5 の 3 段にし、24fps を下回るたびに 1 段ずつ下げる。WebGL のレンダラー名がソフトウェア描画 (SwiftShader・llvmpipe など) なら最初から 0.5 で描く
  - dpr は範囲で渡す形のまま (2026-10-21 の追記) だが、下限は 1 から 0.5 に変わった
  - 動画への置き換え・シェーダーの簡略化はしない (仕様で合意した見た目と、つなぎ目の無いループを保つため)
  - 本物の GPU の端末での負荷は確かめていない
