# 0028. お問い合わせの届け先は Slack だけにし、応答の前に送って結果を確かめる

- 状態: 提案中
- 日付: 2026-10-13
- 関連: [PBI-0018](../pbi/0018-contact-form/PBI.md)、[仕様](../specs/contact-form.md)、[ADR 0018](0018-slack-notify-decorator.md)

## 背景

- 閲覧者が持ち主に連絡する手段を、持ち主のメールアドレスを公開せずに用意したい
- サイトの通知は、/now の投稿とチャットの質問の両方が Slack の 1 つのチャンネル (`SLACK_WEBHOOK_URL`) に届いている。持ち主は通知をここに統一したい
- ADR 0018 の `withSlackNotify` は、応答を返したあとに送り、送れなくても API を失敗させない (通知は付け足しの機能という前提)
- お問い合わせでは、Slack が唯一の届け先になる。後から送って失敗を許すと、送り主には「受け付けました」と出たまま、お問い合わせが誰にも届かずに消える
- サイトから送り主にメールを返すと、入力されたアドレス宛てにメールを送る踏み台にされたり、送信元のドメインの評判が落ちたりする

## 決定

- お問い合わせの届け先は **Slack だけ**にする。送り先は全体共通の `SLACK_WEBHOOK_URL`。メールは送らず、送り主への自動返信もしない。持ち主は通知に載った送り主のメールアドレスへ手で返信する
- `POST /api/contact` では `withSlackNotify` を使わず、`notifySlack` を**応答の前に**呼んで結果を待つ。送れたら 200、送れなかったら 502 を返す。`SLACK_WEBHOOK_URL` が無ければ 503 を返す
- 通知には名前・メールアドレス・本文の全文・受け付けた日時を載せ、送り主が書いた文字列はすべて `escapeSlackText` で無害化する。IP アドレスは載せない
- お問い合わせはどこにも保存しない
- 連打と bot は、チャットと共通化した IP ごとのレート制限 (お問い合わせは 1 時間 5 回) とハニーポットで抑える
- `testing/e2e-policy.yml` の外部モック観点 (external-mock) の対象に `/contact` と `/api/contact` を足す。テストから本物の Slack を呼ばないため

## 検討した選択肢

| 選択肢                                | 良い点                                                                                          | 悪い点                                                                                |
| ------------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| **Slack だけ・応答の前に送る (採用)** | 通知の場所が 1 つ。外部サービスもドメインの設定も増えない。届かなかったことを送り主に伝えられる | Slack が落ちているあいだは受け付けられない。応答が Slack の分だけ遅くなる (上限 5 秒) |
| `withSlackNotify` で後から送る        | 既存のデコレータをそのまま使える                                                                | Slack が落ちているとお問い合わせが黙って消える                                        |
| メール (Resend など) で送る           | メールで受け取れる                                                                              | 送信元ドメインの認証と評判の管理が要る。通知の場所が 2 つに分かれる                   |
| 保存してから通知する                  | 通知に失敗しても残る                                                                            | 個人情報を持つ場所が増える。管理画面が要る                                            |

## 結果

- 送り主には、Slack に届いたときだけ「受け付けました」と出る
- `SLACK_WEBHOOK_URL` は /now・チャットに加えてお問い合わせでも必須になる。外すとお問い合わせは 503 になる
- 外部モック観点が `/contact` と `/api/contact` にも掛かり、`pnpm test:coverage-map -- --check` が穴を見る
- レート制限はメモリ内の目安のままなので、インスタンスが分かれると上限より多く通ることがある。足りなくなったら Upstash Redis で数える形に上げる (新しい ADR)
