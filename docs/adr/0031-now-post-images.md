# 0031. /now の記事の画像: 記事と一緒に multipart で受け、public の Blob に置いて対応表で描く

- 状態: 提案中
- 日付: 2026-10-21
- 関連: [PBI-0024](../pbi/0024-now-post-images/PBI.md)、[仕様](../specs/now-post-images.md)、[ADR 0015](0015-now-posts-storage-and-markdown.md) (画像の部分を置き換える)、[ADR 0019](0019-chat-docs-external-store.md)、[ADR 0024](0024-works-detail-data-and-diagrams.md)

## 背景

ADR 0015 で、/now の記事は「画像の埋め込みは扱わない」と決めた。
持ち主は、D2 で描いたライト用・ダーク用の SVG の図を含む技術記事を /now に載せたい。手元の記事は GitHub 向けに `<picture>` で図を入れているが、/now は生の HTML を描かない。
一方、今の描画は `![](https://任意のホスト)` を素の `<img>` で描いていて、外部の画像を止める仕組みが無い。
Vercel Blob は public / private がストアごとに決まり、あとから変えられない。今あるストアはチャットの資料用の private (ADR 0019) で、ブラウザから直接は読めない。
Vercel の関数はリクエストの本文を 4.5MB までしか受けない。

## 決定

- **受け口**: 今ある `POST /api/now`・`PUT /api/now/[id]` の multipart に、`images` 欄 (何度でも) を足す。.md と画像を 1 回で送る。別の画像の API は作らない
- **本文の書き方**: 手元のファイルのままの相対パス `![代替テキスト](assets/x-light.svg)`。サーバーはファイル名 (最後の `/` より後ろ) で、本文の画像と送られたファイルを結び付ける。本文は相対パスのまま保存し、記事に対応表 `images` (ファイル名 → URL・幅・高さなど) を持たせて、描くときに引く
- **置き場**: /now 専用の **public** の Vercel Blob ストアを新しく作る。パスは `now/<記事 id>/<SHA-256 の先頭 16 桁>-<ファイル名>` で不変、キャッシュは 1 年。トークンは専用の `NOW_IMAGES_BLOB_READ_WRITE_TOKEN` を SDK に明示して渡す
  - トークンが無いとき、開発中と `NOW_POSTS_STORE=memory` (E2E) ではメモリに置き `data:` URL を返す。本番では画像つきの投稿だけ 503
- **受け付けるもの**: 本文から参照された画像だけ。外部の画像・送られていない画像・使われていないファイル・同じ名前の重複・代替テキストが空、はどれも 400。形式は SVG・PNG・JPEG・WebP を中身で判定し、1 枚 1MB・20 枚まで、リクエスト全体は 4MB まで (超えたら 413)
  - SVG は `<script>`・`on*` 属性・`<foreignObject>`・外部の参照を含めば断る。中身を書き換えて無害にはしない (投稿できるのはトークンを持つ持ち主だけなので、断れば足りる)
- **画像の組**: `<基>-light` と `<基>-dark` を一緒に送ると組になり、サイトのテーマ (next-themes の dark クラス) に合う方だけを出す。`<picture>` (OS の設定で切り替わる) は使わない (ADR 0024 と同じ理由)
- **描画**: 対応表にある画像だけを素の `<img>` (幅・高さ付き、遅延読み込み) にする。対応表に無い画像は代替テキストの文字にする。`images.unoptimized: true` なので next/image は使わない
- **拡大表示**: /works の `ArchitectureViewer` を汎用の画像の拡大表示にして共通の部品に移し、記事の画像を押すと開く
- **更新と削除**: PUT は、今回送ったファイル → 元の対応表の順で探し、参照されている画像だけを残す。PUT で外れた画像と DELETE した記事の画像は、記事の操作が成功したあとに Blob から消す。消すのに失敗しても成功のまま返し、ログに残す
- ADR 0015 のうち「画像の埋め込みは扱わない」だけをこの ADR で置き換える。保存先・認可・Markdown と Mermaid の描き方・生の HTML を描かないことは ADR 0015 のまま

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| **記事と一緒に multipart で送る (採用)** | Postman でファイルを選ぶだけで済む。同じ .md が GitHub でもサイトでも表示できる。Blob の資格情報が手元に要らない | 入力の検査と対応表、後始末をサーバーが持つ。1 回の送信が 4.5MB に縛られる |
| 手元のスクリプトで Blob に上げ、本文を絶対 URL に書き換えて投稿する | サーバーの投稿 API を変えずに済む | 手元に public ストアのトークンが要る。投稿用の写しと原本の 2 つができる |
| 画像だけを受ける別の API を作り、返った URL を本文に手で書く | API の責務が分かれる | 2 段の手順になり、URL の書き換えを手でやる |
| **public の Blob ストアを新しく作る (採用)** | 別オリジンで Vercel が CSP と nosniff を付けて配る。配信ルートも関数の転送料も要らない | ストアが 2 つになる。URL を知っていれば誰でも読める (公開記事の画像なので問題ない) |
| 今の private ストアに置き、サイトの配信ルートで返す | ストアが 1 つで済む | 同じオリジンから SVG を返すので CSP・sandbox を自分で付ける。転送が関数を通り費用がかかる |
| 署名付き URL を本文に埋める | 関数を通さずに private を配れる | 期限が最長 7 日で、ページのキャッシュとずれると画像が切れる |
| `<picture>` の生の HTML を一部だけ許す (rehype-raw + sanitize) | 手元の記事をそのまま貼れる | 生の HTML を描かない決まりに例外ができる。テーマが OS の設定で切り替わり、サイトのテーマとずれる |
| SVG をサーバーでサニタイズする | 危ない SVG も載せられる | 依存が増え、D2 の図の見た目が変わるおそれがある。投稿者は持ち主だけなので断れば足りる |

## 結果

- 持ち主は、記事の .md と画像を Postman か curl で 1 回送るだけで、図つきの記事を公開できる
- 外部の画像は描かれなくなる (前からある記事に外部の画像があれば、代替テキストの文字になる)
- 本文の画像の参照を構文木で拾うため、`unified`・`remark-parse`・`unist-util-visit` を直接の依存に足す (どれも react-markdown が既に使っているもので、版も lockfile に合わせる。正規表現ではコードの中の `![]()` を誤って拾うため)
- 新しい環境変数 `NOW_IMAGES_BLOB_READ_WRITE_TOKEN` と、/now 用の public の Blob ストアが増える。作成と設定は持ち主が Vercel の管理画面で行う
- /works の拡大表示は共通の部品になるが、見た目と動きは変えない
- E2E は画像もメモリに置き、本物の Blob に書かない。`testing/e2e-policy.yml` と CI の設定は変えない
- 画像の最適化・定期的な掃除・サイト全体のセキュリティヘッダは扱わない。必要になったら別の PBI で考える
