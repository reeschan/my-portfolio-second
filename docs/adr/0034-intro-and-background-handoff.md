# 0034. トップの導入演出と、3D 背景への引き継ぎ

- 状態: 提案中
- 日付: 2026-10-23
- 関連: [PBI-0029](../pbi/0029-intro-loader/PBI.md)、[0012](0012-background-themes.md)、[0004](0004-design-theme.md)、[docs/specs/intro-handoff.md](../specs/intro-handoff.md)

## 背景

トップを開いたとき、3D 背景の読み込み (three.js の読み込みとシェーダーのコンパイル) が終わるまで時間がかかる。その間はブラウザの手がふさがり、「Enter」を押しても反応が遅れることがある。読み込み中の画面には何も起きず、閲覧者には「重いサイト」に見える。

持ち主は、読み込みの時間をただ待たせるのではなく、自分のキャラクターを使ったスタイリッシュな演出で埋め、そのあいだも入口はすぐ押せるようにしたい。あわせて、次のことを決める必要がある。

- 導入演出をいつ流すか (サイト内の移動で戻ったとき・ほかのページから入ったとき・言語を切り替えたとき)
- three.js をいつ読み込み、背景の準備完了をどう知らせ、いつ 3D 背景へ引き継ぐか
- 引き継ぎの判断をどこに置き、どう守るか
- 導入演出の CSS と色をどこに置くか

## 決定

- **トップを読み込んだときにだけ、5 秒の導入演出を背景に流す。** サイト内の移動で戻ったとき・ほかのページから入ったとき・言語を切り替えたときは流さない
  - サーバーで描く最初の HTML には常に導入演出を含める (サーバーでは背景の準備完了にならないので、ハイドレーションと食い違わない)。描いた時点で背景の準備完了が来ていれば出さない
  - 言語の切り替えでは導入演出の部品を描き直さないので、流れ直さない
- **3D 背景は全ページで、ブラウザの手が空いてから読み込む。** `requestIdleCallback` に 2 秒の timeout を付け、無いブラウザでは `setTimeout` で始める。最初の 1 枚を描いたら「背景の準備完了」を知らせる
  - 読み込みの時刻と背景の準備完了は `lib/background-load.ts` の小さなストア (購読と取得) で全ページが共有する。背景テーマのストア (0012) と同じ形にする
  - トップでは、3D 背景は導入演出の下で透明のまま読み込み・描画を進め、引き継ぎで見えるようにする
- **導入演出が終わり、かつ背景の準備完了になったら、約 1 秒かけて重ねて引き継ぐ。** 終わって 8 秒たっても準備完了にならなければ、あきらめて最後の姿を背景として残し、見出しを見せる
  - 待つあいだは最後の姿のまま、数秒おきにゆっくり瞬きを繰り返す。進み具合の数字は出さず、バーは飾りとして 5 秒で満ちる
- **引き継ぎの判断は React から切り離した純粋な関数に置く** (`lib/intro/handoff.ts`)。出来事と状態は定数オブジェクトの union で表し、出来事の順番の組み合わせを Vitest で守る
  - 導入演出の終わりと背景の準備完了は、どちらが先でも引き継ぎ済みになる。引き継ぎ済みとあきらめは、その後の出来事で変わらない
  - 入口が押されたら打ち切って /overview へ移る
- **見出しは導入演出のあいだ透明度 0 で置く。** 最初の HTML とスクリーンリーダーには含め、引き継ぎ (またはあきらめ) のあとに見せる
  - 入口は最初から押せるリンクとして置き、押すと導入演出を打ち切って本文へ移る
- **LCP を遅らせないため、キャラクターは最初から薄くぼかして見せる。** 透明度 0 から始めず、だんだんはっきりさせる
- **導入演出の CSS は、部品の隣の CSS Modules に置く** (`components/features/intro/intro.module.css`)。破片の形・光の帯・マスクは Tailwind のクラスで書きにくく、`globals.css` に入れると全ページで読まれるため。色はトークンから取る
- **演出は動画ファイルではなく CSS で動かす。** 動画は 5 秒で約 1MB、CSS と絵 2 枚なら約 190KB で済む。JS は、名前を 1 文字ずつ分けることと、導入演出の終わりを知らせることだけに使う
- **視差効果を減らす設定**ではアニメーションを止め、目を開けたカードを 1 秒ほど見せたら導入演出が終わったとみなす。3D 背景は止まった 1 枚で引き継ぐ
- **色とボタンの質感はトークンとユーティリティで持つ。** 演出用の色 (`intro-backdrop`・`intro-pink`・`intro-violet`・`intro-teal`・`intro-red`) とガラスの縁の光 (`glass-highlight`) を `globals.css` に足し、[0004](0004-design-theme.md) と [theme.md](../design/theme.md) に載せる。入口のガラス調は `glass-button` として共通のユーティリティにする
- **読み上げと文言**: 導入演出の英字 (名前・「PORTFOLIO · LOADING」) は飾りとして読み上げから外す。読み上げ用の「読み込み中」は画面の固定の文言 (日本語が正本、英語版も用意) に足す

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 動画ファイルを流す | 試作した見た目をそのまま出せる。実装は video を置くだけ | 5 秒で約 1MB。最初の表示が重くなり、回線が遅いと演出そのものが待たされる。端末の大きさに合わせた作り直しも要る |
| 画面全体を覆うローディング (読み込みが終わるまで押せない) | 読み込みが終わるまで確実に待たせられる。実装が単純 | 閲覧者は押せず、待たされている感じが増す。準備完了が遅いと入口にたどり着けない |
| 演出を流さず、遅延読み込みだけ | 実装が最も軽い。本文の表示を妨げない | 読み込み中の画面が何も起きず、「重いサイト」に見える。待ち時間を演出で埋める狙いを満たさない |
| **CSS の演出 + 遅延読み込み + 引き継ぎ (採用)** | 軽く (約 190KB)、最初から入口を押せる。three の読み込みでボタンの反応を遅らせない。準備が間に合わなくても最後の姿が残る | CSS と絵を自前で保つ。シェーダーのコンパイルの瞬間にぼかしの動きがカクつくことがある |

## 結果

- トップを開くと、3D 背景の準備を待たずに導入演出が動き出し、そのあいだも入口を押せる
- 3D 背景は全ページで手が空いてから読み込むので、どのページもボタンの反応が遅れにくい
- 受け入れること
  - シェーダーのコンパイルの瞬間に、ぼかしの動きがカクつくことがある (透明度と位置の動きは止まらない)
  - 3D 背景が出るのが全ページでわずかに遅れる
  - 背景の準備完了にならないまま 8 秒たつと、導入演出の最後の姿が背景として残る
  - E2E の引き継ぎのテストは、背景の準備完了を待つため 15 秒ほど待つ
- 引き継ぎの判断は純粋な関数なので、出来事の順番の組み合わせを Vitest (`test/lib/intro/handoff.test.ts`) で守れる。トップの見た目と振る舞いは `e2e/intro.spec.ts` で確かめる
- 演出用の色と `glass-button` はトークン・ユーティリティなので、ほかの画面でも同じ質感を使える。演出の CSS は CSS Modules に閉じ込め、`globals.css` には色とユーティリティだけを足す

- 2026-10-24 追記 ([PBI-0032](../pbi/0032-intro-complete/PBI.md)、[docs/specs/intro-complete.md](../specs/intro-complete.md)): 見出しを見せる段と、3D 背景への引き継ぎをやめた。導入演出の最後のコマを着地点にし、完了で止める
  - 理由: PBI-0031 (ADR 0035) で本文にすぐ入れるようになり、引き継ぎ (約 1 秒) と見出しの登場 (0.8 秒) は待ち時間を延ばすだけになった。最後のコマ (カードと名前) のほうが、3D 背景の上の見出しより情報が多い
  - 導入演出が終わり、かつ背景の準備完了になったら (または演出の終わりから 8 秒で)「導入演出の完了」とし、状態の文字を LOADING から COMPLETE! に替える。トップでは導入演出の層を消さず、3D 背景はその下で読み込むだけにして、/overview に入ったときに見せる
  - 見出しは、最後のコマの名前と「Portfolio」を本物の h1 にする。隠した文字は持たない。最初の HTML に見出しと入口を含めることは変えない
  - 判断の純粋関数は `lib/intro/progress.ts` に移し、状態を「演出中・背景待ち・完了・打ち切り」の 4 つにした (引き継ぎ済みとあきらめは、見た目が同じになるので完了にまとめた)。ユニットテストは `test/lib/intro/progress.test.ts`
  - 視差効果を減らす設定では、開いた瞬間に演出が終わったとみなす (1 秒の時計をやめた)。サイト内の移動で戻ったときは、最初から完了の姿を出す
  - 入口で打ち切ったあとも、完了の姿で演出を止める。Cache Components (ADR 0035) では、移った先から戻ると前のページが部品の状態ごと見せ直され (Activity)、CSS のアニメーションだけが頭から流れ直すため。止めるときは、どのアニメーションも始まりを大きく過去にずらし (`animation-delay` を負にする)、終わった姿から描く
  - 3D 背景の遅延読み込み・背景の準備完了の知らせ・LCP のためのキャラクターの見せ方・CSS Modules と色のトークンの置き場は変えない
  - 受け入れること: トップにいるあいだ、見えない 3D 背景を描き続ける (以前も演出の下で描いていたので、新しい負荷ではない)。JS を切ると LOADING のまま残る
