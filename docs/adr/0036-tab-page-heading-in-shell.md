# 0036. タブ付きのページは見出しとパネルの外枠を殻に置き、読み込み中の線は本文にだけ出す

- 状態: 提案中
- 日付: 2026-10-24
- 関連: ADR 0035 (「本文のパネルの位置に、読み込み中の枠を `loading.tsx` で置く」を置き換える)、PBI-0033

## 背景

ADR 0035 で、タブ付きのページの本文のパネルの位置に、読み込み中の枠を `app/(tabs)/loading.tsx` で置いた。先読みが済む前にタブを押すと、この枠が 200〜300ms 出て、見出しが消え、パネルが灰色の線だけになってから新しいページに替わる。替わるのが 2 回になり、ちらついて見える (PBI-0033 の WORK に計測)。

ページの移動は React の transition なので、すでに画面に出ている `<Suspense>` は前の中身を出したまま待つ。一方 `loading.tsx` は、移動先のページごとに新しい `<Suspense>` を作るので、中身が手元に無いとすぐ fallback を出す。

## 決定

- `app/(tabs)/loading.tsx` を置かない
- タブ付きのページは `TabPageTemplate` (`components/layout/tab-page-template.tsx`) で包む。見出し (h1) はタブ名を `LocaleProvider` の言語で出し、本文のパネルの外枠と一緒に殻に置く。Cookie に依る本文 (`"use cache"` の部品) だけを、パネルの中の `<Suspense>` で待つ
  - fallback は読み込み中の線だけ (`PanelBodyFallback`)。見出しとパネルは替わらない
- 見出しがタブ名ではないページ (/now の記事、404) は今までどおり `PageTemplate` を使う

## 検討した選択肢

| 選択肢 | 良い点 | 悪い点 |
| --- | --- | --- |
| 見出しとパネルを殻に置き、線は本文にだけ出す (採用) | 先読みが無いときは、サーバーの応答を待って一度に替わる (手元の計測で枠は 0 フレーム)。殻だけ届いて本文が遅いときも、替わるのはパネルの中だけ | ページの組み立てが「見出し + 本文」の 2 か所に分かれる |
| `loading.tsx` を外すだけ | 変更が最小。先読みが無いときは一度に替わる | 殻だけ届いて本文が遅いとき (/now で保存先の往復が遅いなど) に、待っていることが画面に出ない |
| `loading.tsx` の枠に見出しを出し、線を遅らせて出す | 見出しは消えない | パネルの中身は「前 → 線 → 新」と 2 回替わったまま。遅らせた間はパネルが空になる |
| 今のまま | 変更が無い | ちらつく |

## 結果

- 先読みが済む前に押したときも、見出しは消えず、読み込み中の枠は出ない。前のページのまま待って、一度で替わる
- 先読み済みのときの速さは変わらない
- 直接開いたときに先に出る殻は、共通の枠 (`SiteFrame` の fallback) が今までどおり持つ
- 見出しはクライアントの部品が描くが、サーバーでも描かれるので HTML に h1 が入る
