# 0037. /now の記事の英語版は、投稿のたびに LLM で自動で訳して記事と一緒に保存する

- 状態: 提案中
- 日付: 2026-10-24
- 関連: [docs/specs/now-post-english.md](../specs/now-post-english.md)、[ADR 0026](0026-locale-cookie-and-dictionaries.md) (言語は Cookie)、[ADR 0015](0015-now-posts-storage-and-markdown.md) (記事の保存先)、[ADR 0035](0035-cache-components-and-prefetch.md) (記事の作り置き)、[ADR 0008](0008-chat-llm-and-privacy-eval.md) (チャットの LLM)、[ADR 0018](0018-slack-notify-decorator.md)

## 背景

サイトは英語に切り替えられるが、/now の記事だけは日本語のまま出る。記事は持ち主が日本語で書いて API で投稿するもので、`data/en/` のようにコードに英語版を置く作りにはできない。
英語版を誰が・いつ作り、どこに持つかを決める必要がある。持ち主が毎回英語版を書くのは手間が大きい。

## 決定

- **投稿・書き換えのたびに、サイトが LLM (チャットと同じ Moonshot の Kimi) で英語版を自動で作る**。訳は `after()` で応答のあとに作り、投稿の応答を遅くしない
  - 日本語の題名か本文が変わったときだけ訳し直す。訳し直す間は英語版を外し、古い英語版を出さない
  - 訳はコード・図・画像のパス・URL を残す。訳したあとに画像の参照とコードブロックが元と同じかを確かめ、通らなければ保存しない
  - 失敗したら英語版なしのまま Slack に知らせる。API キーが無い環境 (手元・E2E・CI) では訳さない
- **英語版は記事の値の中に `en` として持つ** (`title`・`body`・`source: "auto" | "owner"`・`updatedAt`)。保存先・キー・作り置きのタグは記事と同じ
- **持ち主の訳で置き換えられる**。記事の API とは別に `/api/now/[id]/en` (PUT・DELETE) と `/api/now/[id]/en/translate` (POST、結果を待って返す) を足す
- **英語版を出すのは画面と記事の metadata だけ**。RSS・Slack の知らせ・検索エンジン (Cookie を持たない) には日本語を出す。URL は言語で分けない (ADR 0026 のまま)
- 英語版の無い記事は、英語のときも日本語で出し、`lang="ja"` と断り書きを添える。自動訳には「Machine-translated」と添える

## 検討した選択肢

| 選択肢                                   | 良い点                                                                                                    | 悪い点                                                                                                                                |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 投稿のたびに自動で訳して保存 (採用)      | 持ち主は日本語で投稿するだけ。表示のたびに LLM を呼ばない。訳が気に入らなければ持ち主の訳で置き換えられる | 外部の LLM への依存と費用が増える。訳ができるまで (数十秒) は英語版が無い。`after()` の中の失敗は応答で返せないので、Slack で知らせる |
| 持ち主が英語版も書いて送る               | サイトは LLM を呼ばない。訳の質を持ち主が決められる                                                       | 毎回の手間が大きく、英語版の無い記事が増えやすい                                                                                      |
| 表示のたびに訳す (作り置きあり)          | 保存の形を変えずに済む                                                                                    | 作り置きが切れるたびに LLM を呼び、待ちと費用が読めない。失敗がそのまま閲覧者に見える                                                 |
| 投稿の応答の中で訳しきる                 | 応答で訳の成否が分かる                                                                                    | 長い記事では応答が数十秒〜分かかり、関数の上限に近づく                                                                                |
| 英語版を別のキー (`now:posts:en`) に持つ | 日本語の記事の値を変えない                                                                                | 読み書きが 2 往復になり、記事の削除と英語版の削除がずれうる。作り置きも 2 系統になる                                                  |

## 結果

- 英語で閲覧する人が /now の記事を英語で読める。持ち主の手間は増えない
- 記事の値に任意の `en` が増える。英語版の無い記事は今までと同じ形で、読み込みの検証は `en` だけ壊れていても記事を捨てない
- `/api/now` の書き込みの API に `maxDuration = 300` を付ける。このプロジェクトは Fluid compute が無効で Hobby の上限が 60 秒だったため (プレビューのデプロイが `invalid_max_duration` で失敗)、`vercel.json` に `"fluid": true` を足して有効にする (Hobby でも上限 300 秒。全関数が Fluid compute で動く)
- 自動訳のプロンプトはチャットのシステムプロンプトではないので、プライバシー eval (ADR 0008) の対象外。訳の質を測る eval は作らない
- テストでは本物の LLM を呼ばない。API の Route Handler と自動訳の部品は `fetch` をモックし、E2E は持ち主の訳を `PUT /en` で仕込む。新しい API は `api-contract` 観点の対象
- 英語版を検索に載せたくなったら、ADR 0026 の「URL で分ける」に置き換える新しい ADR を書く
