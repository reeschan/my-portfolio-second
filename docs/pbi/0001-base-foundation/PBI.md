# PBI-0001 ベース実装の整備 (テーマ・共通コンポーネント・E2E・品質ゲート・開発の型)

- 状態: 完了
- 起票日: 2026-10-06
- 依頼者: リポジトリの持ち主
- 作業記録: [WORK.md](WORK.md)
- 関連 ADR: [0002](../../adr/0002-framework-and-hosting.md)〜[0011](../../adr/0011-self-marketplace.md)

> この PBI は、PBI 駆動の開発の型そのものを作った作業なので、作業と並行して後から起こしている。

## 背景・目的

v0 で作った土台に機能を足してきたため、次の問題があった。

- 色や質感がページごとに直書きされ、デザインの「型」が見えない
- ページが大きな 1 ファイルで書かれ、部品の再利用ができない
- E2E はあるが、表示内容・テーマ・会話の流れなど抜けている観点がある
- チャットの自前プロンプトが個人情報を返さないことを、本物の LLM で確かめる手段がない
- lint がなく、CI が落ちてもマージできてしまう。手元のコミットにも歯止めがない
- 技術やテーマを選んだ理由が残っておらず、エージェントに任せる作業の進め方も決まっていない

これからエージェントに改修を任せていくため、「同じ型で、確かめながら進められる」土台を作る。

## やること

1. 今のデザインから Tailwind のテーマ (トークン) を明文化する
2. 共通コンポーネントを作り、画面を部品の組み合わせで作る構成にする
3. E2E を全体的に足す
4. 技術・テーマの選定理由を ADR として後付けで残す
5. PBI・WORK・ADR を前提にした開発手順を `docs/agents/` に書く
6. `create-pr` スキルを、ベーステンプレート向けの Self 組織 (プラグインマーケットプレイス) に置く
7. README にポートフォリオの概要とアーキテクチャ図を載せる
8. チャットのプライバシー eval を作り、合格した結果を Success ファイルとして残す仕組みにする
9. CI に lint・型チェック・ビルド・テストを並べ、通らなければマージできないようにする
10. コミット前に「E2E が足されているか・通るか」を確かめるスキルを作り、通ったときだけコミットできるようにする

## やらないこと

- 画面の見た目の変更 (テーマは今の見た目を明文化するだけ)
- ページの文言・経歴データの更新
- ライトテーマの作り込み (トークンは用意するが、切り替え UI は作らない)
- 本物の LLM での eval の実行 (API キーが必要なため持ち主が手元で行う)
- GitHub 上のブランチ保護の設定そのもの (権限が要るため、取り込むルールセットのファイルまでを用意する)

## 受け入れ条件

| # | 条件 | 確かめ方 |
| --- | --- | --- |
| 1 | 色・角丸・影・ぼかしがトークンとして定義され、画面がトークン経由で塗られている | e2e/theme.spec.ts (@theme)、docs/design/theme.md |
| 2 | ページが `layout/` `common/` `features/` の部品と `data/` の組み合わせで書かれている | docs/design/components.md、既存の E2E が全部通る |
| 3 | カバレッジ表に穴がない | `pnpm test:coverage-map -- --check` |
| 4 | 追加した E2E が 3 回連続で通る | `pnpm test:e2e --repeat-each=3 <追加ファイル>` |
| 5 | ADR に技術・テーマ・構成・品質ゲートの判断が残っている | docs/adr/README.md の一覧 |
| 6 | PBI/WORK/ADR の手順と雛形がある | docs/agents/development-flow.md、docs/pbi/_template/ |
| 7 | Self マーケットプレイスと create-pr スキルが有効になる | `claude plugin validate .`、`.claude/settings.json` |
| 8 | README に概要とアーキテクチャ図がある | README.md |
| 9 | eval の採点が正しく、基準を満たした結果だけが success/ に残る | evals/privacy/score.test.ts、`pnpm eval:privacy --dry-run` |
| 10 | CI が lint / 型 / ユニット / ビルド / E2E を回し、`ci-ok` が必須チェックになる | .github/workflows/test.yml、.github/rulesets/main.json |
| 11 | 検査を通していないコミットがフックで止まる | scripts/commit-gate-match.test.ts、実際にこの PBI のコミットで確かめる |
