## 進め方 (サブエージェント)

依頼者の指定で、Claude Haiku のサブエージェントを並列に走らせて作った。

1. **候補作り**: 5 テーマ × 4 案 = 20 体を並列に起動。案ごとに構図の方向性を変えて渡した
   - 各エージェントは共通の指示書 (契約: export 名・使ってよい import・`Math.random` 禁止・パネルの裏を暗く保つ など) を読み、
     自分のファイルを検証用ページで開いてヘッドレス Chromium (SwiftShader) で撮影し、画像を見て直す、を 4 回以上繰り返した
2. **選定**: テーマごとに 4 案の画像を比べて 1 案を選んだ (下表)
3. **校正 10 回**: 選んだ案を、毎回別のエージェントが 1 つの観点で直した。テーマ間は並列、テーマ内は順番に
   - R1 他の案の良い所の移植 / R2 空と大気 / R3 主役 / R4 奥行きと地形 / R5 動き / R6 本文の読みやすさ /
     R7 スマホ縦長 / R8 色調 / R9 性能とコード / R10 最終確認
   - 撮影は「素の画面」「本文パネルの模型を重ねた画面」「スマホ縦長」の 3 種
   - Haiku が数回続けて直せなかった所は、ディレクター (メインのエージェント) が直接手を入れた (記録の R2.5 など)

## 記録

- 2026-10-08: 参考に挙げられたサイトは、この環境のネットワーク制限で開けなかった。依頼文 (dark・nature・moon、リアリティ) から方向性を決めた
- 2026-10-08: マシンが 4 コアのため、ワークフローの同時実行数が 2 に制限される。依頼どおり 20 体を並列にするため、エージェントを個別に起動した。
  ソフトウェア描画の撮影は CPU を食うので、撮影スクリプトに同時 3 枚までのロックを入れた (一部のエージェントがロックを外したコピーを作って負荷が上がったため、指示書で禁止した)
- 2026-10-08: エージェントが見つけた落とし穴を指示書に追記した
  - uniforms を `useMemo` の別オブジェクトに書いても材質に届かないことがある (アニメーションと縦横比が止まる)。必ず材質の ref 経由で書く
  - 複数の材質で uniforms のオブジェクトを共有すると、R3F が材質ごとに複製するため片方が更新されない (オーロラの雪が止まっていた。R9 で修正)
  - GLSL の予約語 (`half`、`patch` など) を変数名にしない。`pow` の底が負だと未定義 (NaN の黒い点)
- 2026-10-08: E2E の印 (`data-background-theme`) を canvas から背景の枠へ移した。シーンの遅延読み込み中でも選択中のテーマを確かめられるようにするため。
  あわせて「全テーマがエラーなく描ける」テストは、CI の SwiftShader で重いシェーダーの 1 フレームに数秒かかるため待ち時間を長くした
- 2026-10-08: 検証用ページで時々出た React の警告 ("state update on a component that hasn't mounted yet") は、開発サーバーのファイル監視による再読み込みで出るもので、
  実際のページ (`/overview` を各テーマで開く) では出ないことを確かめた
- 2026-10-08: 見送ったこと
  - 月面のクレーターの影の縁にわずかな段差が残る (影の探索を細かくすると重くなるため)
  - 蛍の森の幹はまだ写真には及ばない。月夜の海の雲の帯の縁がやや直線的
  - 実機の GPU でのフレームレートは測っていない (検証はすべてソフトウェア描画)。各シーンは見えない所の計算を省いて、ノイズの評価回数を 6〜7 割減らした

- R3 (Hero element): 月を近白+暖色に持ち上げ、周縁減光と急に落ちる光輪を追加。雲は月下の帯と低い帯に絞り、海の光の道は連続した帯ときらめきに
- R4 (Depth & landscape): 岬を高い断崖+木立の稜線にし右側に月の縁光、霞で遠近。遠島を追加、灯台の光の帯を霞に広げ、遠い海の波を手前ほど大きく、波頭に淡い照り、22度ハロの赤みを低減

- R6 (Readability): 水平線のすぐ下のきらめきを最大45%抑えて、パネル文字の後ろを静かに。月の道と手前の海は明るいまま。空と雲は変更なし
