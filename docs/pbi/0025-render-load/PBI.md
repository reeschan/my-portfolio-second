# PBI-0025 表示した後の描画を軽くして、サイト全体をサクサクにする

- 状態: 進行中
- 起票日: 2026-10-21
- 依頼者: リポジトリの持ち主
- 作業記録: [WORK.md](WORK.md)
- 関連 ADR: [0012](../../adr/0012-background-themes.md)、[0004](../../adr/0004-design-theme.md) (どちらも更新する)

## 背景・目的

サイトが重く感じる。Lighthouse (2026-10-21、デスクトップ) は Performance 99・LCP 0.8 秒・TBT 0 ms で、読み込みは速い。重さの元は、表示した後に続く描画にある。

- 3D 背景が操作の有無にかかわらず毎フレーム (60fps) 全画面を描いている。解像度は最大 1.75 倍、antialias あり、`powerPreference: "high-performance"` で外付けの GPU を起こしうる。視差効果を減らす設定でも止まらない
- 本文パネル・タブバー・アドレスバーの 3 枚に 12px の背景ぼかしがかかり、下の背景が毎フレーム動くので、ぼかしも毎フレーム計算し直される
- トップの見出しは JS の後にしか描かれず、さらに 0.2〜0.8 秒かけて出る
- グリッドのテーマのマウス追従の球は、バネを毎フレーム動かしているのに位置に反映されず、動かない

見た目をほぼ保ったまま、表示した後の描画の負荷を下げる。

## やること

- 3D 背景の描画を 30fps に間引く。antialias を切る。GPU の指定を既定に戻す。重い端末では解像度を自動で 1 倍に下げる
- 視差効果を減らす設定 (`prefers-reduced-motion: reduce`) では、背景を止まった 1 枚にする
- グリッドのテーマで、マウス追従の球が実際にマウスを追うようにし、毎フレームのバネをやめる。パーティクルの追従を、フレームの数ではなく経過時間で動かす
- 本文パネルのぼかしを弱め (12px → 6px)、面の不透明度を上げる (0.6 → 0.75)。タブバー・アドレスバーは今のまま
- トップの見出しと「Enter」のリンクを、サーバーの HTML に含める。登場の演出は CSS のアニメーションにし、視差効果を減らす設定では演出しない
- ADR 0012・0004 と docs/design/theme.md に、決めたことを書く

## やらないこと

- 言語の Cookie の読み方を変えて、全ページを静的に配ること (ADR 0026 の見直しが要るため、別の PBI にする)
- `<Preload all />` を外す、react-markdown の遅延読み込み、リンクの先読みの変更、画像の最適化
- テーマのシェーダーの中身 (アルゴリズム・ループの回数) の変更
