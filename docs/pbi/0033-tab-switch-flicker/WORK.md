- [x] 直し方を決める — 持ち主の案 (スケルトンは Cookie に依る本文だけ) を試作して測る

## 記録

- 2026-10-24: 再現した。測り方は 2 つ
  - (1) 押してから 1.5 秒、毎フレーム (requestAnimationFrame) と DOM の変化ごとに、見えている h1・読み込み中の枠 (`aria-busy`)・タブバーを数える
  - (2) CDP の screencast で描画のフレームを撮り、タブバー・アドレスバー・パネル・パネルの外の領域ごとの明るさを比べる
- 2026-10-24: 何がちらつくか。`app/(tabs)/loading.tsx` の枠 (`PanelFrameFallback`) が切り替えの途中に出る。見出しが消えてパネルが灰色の線だけになり、それから新しいページに替わる。替わるのが 2 回になるので、ちらついて見える
  - 先読みが済んでいれば枠は出ず、1 回で替わる (本番・手元の本番ビルドとも 25〜60ms)
  - 先読みが済む前に押すと出る。本番 (www.reeschan.pink) で読み込み直後の 1 回目は、枠が 93〜302ms。開発サーバーは先読みしないので、ほぼ毎回 100〜300ms 出る
  - 3D 背景・ガラスのぼかし・タブバー・アドレスバーは、録画の明るさを見ても跳ねていない。`<Activity>` で前のページを隠すところも、h1 が 2 つ見えるフレームや何も無いフレームは無い
- 2026-10-24: なぜ出るか。ページの移動は React の transition なので、すでに画面に出ている `<Suspense>` は前の中身を出したまま待つ。`loading.tsx` は移動先のページごとに新しい `<Suspense>` を作るので、中身が手元に無いとすぐ fallback を出す。PBI-0031 の前は `loading.tsx` が無く、押すと待ってから 1 回で替わっていた (遅いが、ちらつかない)
- 2026-10-24: 直し方。最初は「`loading.tsx` を外す」と「枠に見出しを出して線を遅らせる」を持ち主に示した。持ち主から「スケルトンを出す部分は Cache Component (Cookie に依る本文) だけに絞ればいい」と案が出たので、/career と /skills で試作して測った。先読みが無くても枠は 0 フレームで、先読み済みの速さも変わらなかったので、この形にした
  - 見出しはタブ名なので、共通の枠の `LocaleProvider` の言語でクライアントの部品が描ける。見出しとパネルの外枠を殻に置き、本文だけをパネルの中の `<Suspense>` で待つ
  - スキル・ワーク・チャット・お問い合わせは本文がクライアントの部品だけなので、Cookie を読まずに殻に入る。本文の `"use cache"` の部品は要らなくなった
  - 先読みが無いときは、Next.js がサーバーの応答を待ってから描くので、本文も一緒に届き、線は出ない。サーバーが重く本文が後から流れてくるときだけ、パネルの中に線が出る (手元で E2E を並列に回したときに 33 フレーム出た。見出しとパネルは消えない)
- 2026-10-24: E2E (`e2e/navigation.spec.ts` の「先読みが済む前に押したとき」)。先読みの要求を落とし、押したあとの要求に 300ms の遅れを足して、概要 → 経歴 → スキル → Now → テーマと押す。どのフレームでも見えている h1 と本文のパネルがあることを確かめる。直す前の本番に向けて回すと落ちる (スキルで h1 が消えたフレームが 39)。直した後の本番ビルドでは、並列に負荷をかけても通る
- 2026-10-24: 見送り
  - 押したタブに「読み込み中」の印を付けること。先読み前に押すと前のページのまま約 350ms 待つが、今回は付けない
  - /works を初めて開いたとき、アーキテクチャ図の画像が後から順に出る。画像の読み込みで、ちらつきとは別 (2 回目からは出ない)
  - `/now/<id>` と 404 は見出しがタブ名でないので `PageTemplate` のまま。どちらも `loading.tsx` を使っていない

## 検証

手元の本番ビルド (`pnpm build && pnpm start`) を、GPU のある Chrome で測った。「先読みなし」は先読みの要求を落とし、往復 150ms の遅れを足したもの。タブを 10 回 (概要 → 経歴 → スキル → ワーク → Now → チャット → お問い合わせ → テーマ → 概要 → スキル → 経歴) 押した。

| 条件 | 変える前 | 変えた後 |
| --- | --- | --- |
| 先読みなし: 見出しが消えた回 | 10 回中 6 回 (各 約 290ms) | 0 回 |
| 先読みなし: 読み込み中の枠が見えた回 | 10 回中 6 回 | 0 回 |
| 先読みなし: 押してから見出しが替わるまで (初めて開くページ) | 約 480ms | 約 350ms |
| 先読み済み: 押してから見出しが替わるまで | 27〜63ms | 28〜56ms |
| 開発サーバー: 枠が見えた回 | 10 回中 3 回 (100〜300ms) | 0 回 |

- 一度開いたページに戻るとき (最後の 3 回) は、どちらも 30ms 前後で替わる
- ビルドの表は変える前と同じ (タブ付きの 8 ページ・トップ・404 が ◐)
- 先読み済みのときの速さは PBI-0031 と同じ程度のまま (PBI-0031 の手順では約 19ms)
