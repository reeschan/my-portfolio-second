# ガラスの背景テーマと、すぐ切り替わるページ

- 状態: 合意済み (2026-10-23、design-flow の grilling と試作で持ち主と合意)
- PBI: 0030 (ガラスのテーマ) → 0031 (ページの切り替えの性能) の順に、PBI-0029 の上に積む
- 用語: [CONTEXT.md](../../CONTEXT.md) の「背景とトップ」(背景テーマ・ループ・引き継ぎ) と「ページの切り替え」(ページの殻・中身・先読み)
- 関連: ADR 0012 (背景テーマ)、0026 (言語は Cookie)、0034 (導入演出と引き継ぎ)、PBI-0025 (描画の負荷)

## Problem Statement

持ち主は、導入演出で作ったガラス調の見た目が気に入っていて、導入演出が終わったあとの 3D 背景も同じ世界観でつなげたい。今の既定の背景テーマ (グリッド) は青い格子で、紫のガラスの導入演出から引き継ぐと見た目が急に変わる。

また、サイト内でタブを押してから中身が替わるまでの待ちが長く、サイトが重く感じる。全ページがリクエストごとにサーバーで描かれていて (ルートのレイアウトが Cookie で表示言語を読むため)、読み込み中の表示も先読みもないので、押してもサーバーが描き終わるまで何も起きない。/now はさらに、移るたびに外部のデータベースを往復する。

## Solution

- 新しい背景テーマ「ガラス」を足し、既定のテーマにする。暗い紺の地に紫の柔らかい光の玉が漂い、ガラスの破片がゆっくり揺れたり回ったりし、光の帯がときどき横切り、塵が舞う。画面全体に薄いスモークがかかって落ち着いた暗さになる。動きは 10 秒でつなぎ目なくループする
- ページは、閲覧者や表示言語に依らない「ページの殻」をすぐに出し、表示言語で描く「中身」は先読みで手元に取っておく。タブを押した瞬間に切り替わる。表示言語は今までどおり Cookie で持ち、URL は変えない
- /now は記事の投稿・削除のときだけ作り直し、ふだんは作り置きを配る
- 重いライブラリ (グラフと Markdown) は、使うときに読み込む

## User Stories

ガラスのテーマ

1. 初めて訪れた閲覧者として、導入演出から同じ紫のガラスの世界観の背景に引き継がれてほしい。見た目が急に変わらないようにするため
2. 閲覧者として、背景がゆっくり動き続けてほしい。止まった壁紙より、作り込まれたサイトだと感じられるようにするため
3. 閲覧者として、背景の動きに切れ目やカクつきが見えないでほしい。10 秒ごとに映像が飛ぶと気になるため
4. 閲覧者として、背景は暗く落ち着いていてほしい。本文の文字が読みにくくならないようにするため
5. 閲覧者として、/theme の一覧で「ガラス」を選べてほしい。ほかのテーマから戻せるようにするため
6. すでにほかのテーマを選んだ閲覧者として、既定が変わっても自分の選んだテーマのままであってほしい
7. 視差効果を減らす設定の閲覧者として、ガラスのテーマでも背景が動かないでほしい
8. 性能の低い端末の閲覧者として、ガラスのテーマがほかのテーマより重くないでほしい
9. 英語で見る閲覧者として、/theme のガラスのテーマの名前と説明が英語で出てほしい
10. 持ち主として、ガラスのテーマの色はトークン (導入演出と同じ紫・ピンク・青緑・地の紺) から取ってほしい。導入演出と色がずれないようにするため

ページの切り替え

11. 閲覧者として、タブを押したらすぐ中身が替わってほしい。サイトが固まっていると感じないようにするため
12. 閲覧者として、タブを押したときにタブバーとアドレスバーがちらつかないでほしい。ページの外枠は同じままであってほしいため
13. 閲覧者として、まだ先読みが終わっていないページに移るときは、本文のパネルの位置に読み込み中の枠がすぐ出てほしい。押したことが伝わるようにするため
14. 英語で見る閲覧者として、ページを直接開いたときに、日本語が一瞬見えてから英語に替わる、ということが起きないでほしい
15. 英語で見る閲覧者として、ページを直接開いたときに、表示がずれないでほしい (タブバーの場所は先に空のガラスの帯で取っておく)
16. 閲覧者として、言語を切り替えたあとにタブを押したら、切り替えた言語で中身が出てほしい。先読み済みの前の言語の中身が出ないようにするため
17. スクリーンリーダーの利用者として、ページの `lang` が表示言語と合っていてほしい
18. 閲覧者として、/now を開いたときに外部のデータベースの往復を待たされないでほしい
19. 持ち主として、記事を投稿・削除したら、そのあと /now を開いた人にはすぐ反映されてほしい。すでにサイトを開いている人には、最大 5 分の遅れを受け入れる
20. /skills を開かない閲覧者として、グラフのライブラリを読み込まされないでほしい
21. /works の詳細を開かない閲覧者として、Markdown のライブラリを読み込まされないでほしい
22. JS が動かない閲覧者やリンクのプレビューとして、トップの見出しと入口は見えてほしい
23. 検索エンジンやリンクのプレビューのクローラーとして、どのページでもタイトルと本文を受け取りたい
24. 持ち主として、変える前と後で、タブを押してから切り替わるまでの時間が縮んだことを数字で確かめたい

## Implementation Decisions

ガラスのテーマ (PBI-0030)

- 背景テーマの一覧に `glass` を足し、並びの先頭に置き、既定のテーマ (`defaultBackgroundThemeId`) を `glass` にする。保存済みの選択は今までどおり優先する。表示名と説明は `data/messages` の言語ごとの文言に足す (「ガラス」/「Glass」)
- シーンは既存のテーマと同じく 1 テーマ 1 ファイル (ADR 0012)。中身は全画面を覆う 1 枚の面に 1 つのフラグメントシェーダーで描く。ガラスの屈折は、背景を別の絵に描いてから歪める方法 (1 フレームに 2 回描く) を使わず、地を表す関数をずらした座標でもう一度呼ぶ「見た目だけの屈折」にする
- ループ: すべての動きを、10 秒で 1 周する位相 `ang = 2π × (経過秒 / 10)` の関数にする。円の位置・回転・明滅は位相の整数倍の sin・cos、ノイズは場を位相の円の上で動かす。塵は場を流さず、各粒が自分のセルの中で小さな円を描く (場を流すと 1 周で隣のセルの粒に入れ替わり、つなぎ目が出るため。試作で確かめた)。経過秒はループの長さで割った余りにして、浮動小数の精度が長時間で落ちないようにする
- 見た目は試作 (`docs/pbi/notes/glass-theme-prototype.html` の案 A、コミットしない) が正本。要点:
  - 地: `intro-backdrop`、下ほど少し明るい
  - 光の玉: 紫 (`intro-violet`) が主役の 2 つ、ピンク・青緑は小さく 1 つずつ。スクリーン合成
  - ガラスの破片: 7 枚の平行四辺形。多くは元の角度のまわりで揺れ、一部は 1 周で 1 回転。面は地をずらして写して明るくにじませ、縁は上を向いた側ほど明るく光る
  - 光の帯: 10 秒に 2 回、斜めに横切る。破片の上で強く光る
  - 塵: 3 層
  - スモーク: ゆがめたノイズの煙で全体を覆う。濃さ 0.7、全体の明るさ 0.8 (試作で持ち主が決めた値)
- 試作から移す式の要点 (試作の GLSL から):

  ```glsl
  float loopFbm(vec2 p, float ang, float r) { return fbm(p + r * vec2(cos(ang), sin(ang))); }
  float smokeField(vec2 uv, float ang) {
    vec2 q = vec2(loopFbm(uv * 1.1, ang, 0.7), loopFbm(uv * 1.1 + 5.2, ang + 1.7, 0.7));
    return loopFbm(uv * 1.4 + 1.8 * q, ang + 0.6, 0.45);
  }
  // 色 = mix(色, 煙の色, スモーク × 濃さ × 0.85) + 紫 × 0.035 × スモーク × 煙の筋。最後に明るさを掛ける
  ```

- 色はトークンから取る。シェーダーには `lib/theme.ts` (three.js 用の色) に導入演出の色を足して渡す。シーンの配色はテーマのファイルが持ってよい例外 (ADR 0012) だが、導入演出とずれないようにトークンの値と対応させる
- 30fps の間引き・解像度の自動調整・視差効果を減らす設定 (止まった 1 枚)・背景の準備完了の知らせは、今の仕組みをそのまま使う。視差効果を減らす設定の 1 枚は、位相 0 の姿にする
- /theme のカードの見本のグラデーションは、地の紺・暗い紫・紫の 3 色にする
- ADR 0012 に、2026-10-23 の追記として「既定のテーマをガラスにしたこと」と「ループの作り方」を書く。新しい ADR は書かない (既定はいつでも戻せるため)

ページの切り替えの性能 (PBI-0031)

- `next.config` で Cache Components と Partial Prefetching を有効にする
- 表示言語は今までどおり Cookie で持つ (ADR 0026 は維持)。URL もフォルダの構成も変えない
- ルートのレイアウトは Cookie を読まない。`<html lang="ja">` を既定にし、`<head>` のインラインのスクリプトが描く前に Cookie の言語で `lang` を書き換える (Next.js の文書の「ハイドレーション前のちらつきを防ぐ」形)
- ページは「殻」と「中身」に分ける
  - 殻: ルートのレイアウト、3D 背景、タブバーとアドレスバーの場所 (空のガラスの帯)、本文のパネルの枠、トップの見出しと入口 (言語に依らない)
  - 中身: 表示言語で描くもの。タブの表示名、ページの見出しと本文、言語に依る metadata、言語の文言を使うクライアントの部品 (LocaleProvider で配る)
  - 中身は `<Suspense>` の中で Cookie から表示言語を読み、言語を引数にした `"use cache"` の関数・部品で描く。先読みに入れるため、キャッシュの有効期間の `stale` は 5 分以上にする。Cookie を直接読む部分を先読みに入れる必要があれば `"use cache: private"` を使う
- タブバーとアドレスバーは各ページから共通のレイアウトに移し、サイト内の移動では描き直さない。表示名は中身として届く
- 本文のパネルの位置に、読み込み中の枠 (パネルの枠だけ、`aria-busy`) を `<Suspense>` の fallback として置く
- 言語の切り替え (Server Function で Cookie を書く) のあとは、先読み済みの中身を捨てて、新しい言語で描き直す
- /now と記事のページ: 記事の読み込みを `"use cache"` にし、`cacheTag` を付ける。投稿・削除の API の成功時に、そのタグを `revalidateTag` で作り直す。今の `connection()` と `no-store` は外す。記事のページは既知の記事を作り置きし、未知の記事は初回に作る (ISR)
- 遅延読み込み: /skills のグラフ (recharts) と、/works の詳細ダイアログの Markdown (react-markdown) を `next/dynamic` で読み込む。読み込み中の見た目は場所を取っておき、表示がずれないようにする
- `generateMetadata` も、言語を引数にした `"use cache"` で描く。クローラーには Next.js が利用者のエージェントで見分けて、最初から全部描いて返す (htmlLimitedBots の既定の一覧)
- 新しい ADR 0035 に、Cache Components と先読みを採ったこと、ルートのレイアウトで Cookie を読まないこと、JS を切った閲覧者の扱い、比べた案 (proxy で言語ごとの静的なページに振り分ける、URL で言語を分ける、読み込み中の表示と先読みだけ) を書く。ADR 0026 に、描き方が 0035 に移ったことを追記する

## Testing Decisions

- よいテスト: 閲覧者から見えるもの・押せるもの・移る先だけを確かめる。シェーダーの中身、キャッシュの関数の呼ばれ方、`<Suspense>` の置き場所は確かめない
- 性能の自動テストは足さない (`testing/e2e-policy.yml` の performance は「個人サイトで現状は不要」)。代わりに次の 3 つで確かめ、結果を WORK に残す
  - ビルドのルートの表で、ページが部分的に作り置き (◐) か作り置き (○ / ●) になり、ƒ でないこと
  - 本番に近いビルド (`pnpm build && pnpm start`) で、タブを押してから見出しが替わるまでの時間を、変える前と後で同じ手順で測る
  - Vercel のプレビューを持ち主が触る

合意済みの seam

1. `e2e/background-theme.spec.ts`: テーマの一覧を回して全テーマの描画を確かめる既存のテストに、ガラスが自動で入る。足すのは「保存のない閲覧者の既定がガラス (`data-background-theme="glass"`)」と「保存済みのテーマは既定の変更で変わらない」
2. `test/lib/background-theme.test.ts`: 既定のテーマの id と一覧の並び (先頭がガラス) を、既存のテストの形で確かめる
3. `e2e/navigation.spec.ts`: タブを順に押して全ページを巡回する既存のテストが通ること。足すのは「タブを押してもタブバーが描き直されない」(押す前に取ったタブバーの要素が、押した後も同じ要素として残っている)
4. `e2e/i18n.spec.ts`: 足すのは「英語に切り替えたあと、先読み済みのタブを押すと英語の中身が出る」と「英語の Cookie で直接開いたとき `<html lang="en">` になる」
5. `e2e/home.spec.ts`: 「JS を切ってもトップの見出しと Enter が見える」をそのまま守る
6. `e2e/now.spec.ts` と `test/app/api/now/`: 投稿・削除の後に /now を開くと反映されていること (E2E)。API の成功時にタグの作り直しを呼ぶこと (ユニット。`next/cache` をモックする、既存の `next/server` のモックと同じ形)
7. `e2e/seo-*.spec.ts`: 全ページのタイトル・説明・構造化データの既存のテストが通ること (metadata を作り直しても壊れていない)

先例: 背景テーマの E2E (`background-theme.spec.ts`)、言語の E2E (`i18n.spec.ts`)、/now の API のユニット (`test/app/api/now/`)、JS を切った E2E (`home.spec.ts`)

## Out of Scope

- 動画ファイルで背景を流すこと (シェーダーで描くと決めた)
- 導入演出の見た目の変更
- ほかの背景テーマのシェーダーの中身の変更と、テーマの削除
- 表示言語を URL で分けること、proxy で言語ごとのページに振り分けること
- 本物の屈折 (別の絵に描いてから歪める) と、ガラスの破片のマウスへの反応
- 性能の自動テスト (Lighthouse CI など)
- 本文のパネルのぼかしの強さの変更 (PBI-0025 で決めた 6px のまま)
- JS を切った閲覧者に、トップ以外のページの本文を見せること
