# トップの導入演出の完了 (COMPLETE! で止まり、入口から本文へ)

- 日付: 2026-10-24
- 状態: 合意済み (design-flow の grilling で持ち主と確認)
- 改める仕様: [intro-handoff.md](intro-handoff.md) のうち、導入演出の終わり方 (3D 背景への引き継ぎと、見出しを見せる段)。導入演出そのものの流れ・3D 背景の遅延読み込み・背景の準備完了の知らせは、intro-handoff.md のまま
- 用語: [CONTEXT.md](../../CONTEXT.md) の「背景の準備完了」「導入演出」「導入演出の完了」「入口」

## Problem Statement

PBI-0031 で、タブを押してから中身が替わるまでが 340ms から 19ms ほどになった。本文にはすぐ入れるようになった。
ところがトップでは、5 秒の導入演出のあと、3D 背景の準備完了を待って約 1 秒かけて引き継ぎ、さらに 0.8 秒かけて見出し「Ryuki Tobita Portfolio」を見せている。この段は、閲覧者にとって待ち時間を延ばすだけになっている。
また、引き継ぎのあとのトップは「3D 背景の上に見出しと Enter」で、導入演出の最後のコマ (キャラクターのカードと名前) より情報が少ない。

## Solution

導入演出の最後のコマを、トップの着地点にする。導入演出が終わり、かつ背景の準備完了になったら (導入演出の完了)、状態の文字が「LOADING」から「COMPLETE!」に替わる。そこで一度光り、進み具合のバーの最後の 1 割が満ちる。入口の「Enter」は縁の光が脈打って少し目立つ。
トップでは 3D 背景に切り替えない。3D 背景は裏で読み込むだけにし、Enter で /overview に入ったときに初めて見える。
別に置いていた見出しは無くす。かわりに、最後のコマに大きく出ている名前「RYUKI TOBITA」と、その下の「PORTFOLIO」を、本物の見出し (h1) にする。

## User Stories

1. 閲覧者として、導入演出が終わったら、そのコマのまま「COMPLETE!」で準備ができたと分かりたい。3D 背景と見出しが出るまで、さらに待たされないようにするため
2. 閲覧者として、COMPLETE! が出たら、Enter が少し目立ってほしい。次に何をすればよいかが分かるようにするため
3. 閲覧者として、導入演出の最中でも Enter を押して本文へ進みたい。演出を見たくないときに待たなくて済むようにするため
4. 閲覧者として、導入演出の途中で Enter を押したら、演出が打ち切られて本文へ移ってほしい
5. 閲覧者として、Enter で /overview に入ったら、3D 背景がもう描ける状態で出てほしい。導入演出のあいだに裏で読み込んだ分、待たずに済むようにするため
6. 閲覧者として、回線が遅くて 3D 背景の準備が間に合わないときは、最後のコマで瞬きしながら LOADING のまま待ちたい。何も起きない時間ができないようにするため
7. 閲覧者として、背景の準備完了にならないまま待ち続けても、導入演出が終わって 8 秒たったら COMPLETE! を見たい。LOADING のまま止まって見えないようにするため
8. WebGL が使えない端末の閲覧者として、3D 背景が出なくても、8 秒後に COMPLETE! になり、Enter から本文へ進みたい
9. 閲覧者として、進み具合のバーが満ちたのに LOADING のまま、という食い違いを見たくない。バーは 5 秒で 9 割まで満ち、残りは COMPLETE! で満ちてほしい
10. 閲覧者として、サイト内を移動してトップに戻ったときは、導入演出を流さず、COMPLETE! の最後の姿をいきなり見たい。同じ演出を何度も待たされないようにするため
11. 閲覧者として、トップ以外のページから直接サイトに入ったときは、導入演出なしで 3D 背景を見たい
12. 閲覧者として、導入演出の途中で言語を切り替えても、演出を最初からやり直されたくない
13. 視差効果を減らす設定にしている閲覧者として、動く演出を見せられたくない。最後の姿 (目を開けたカード・名前・満ちる前のバー) をいきなり見て、準備ができたら動きなしで COMPLETE! に替わってほしい
14. 視差効果を減らす設定にしている閲覧者として、COMPLETE! で光ったり、Enter が脈打ったりしてほしくない。Enter は縁の光を強めるだけにしてほしい
15. スクリーンリーダーの利用者として、名前と「Portfolio」を、このページの見出しとして読みたい。何のサイトかが分かるようにするため
16. スクリーンリーダーの利用者として、飾りの英字 (「LOADING」「COMPLETE!」) を読み上げられたくない。かわりに、導入演出の領域の名前で、表示言語に合わせた「読み込み中」「読み込み完了」を知りたい
17. スクリーンリーダーの利用者として、完了の時点で読み上げを割り込まれたくない。Enter は最初から押せるので、完了を待つ必要がないため
18. 検索エンジンやリンクのプレビューとして、見出しと入口が最初の HTML に含まれていてほしい。JS を動かさなくてもページの中身が分かるようにするため
19. 検索エンジンとして、隠した文字ではなく、画面に見えている文字を見出しとして受け取りたい
20. JS を切った閲覧者として、見出しと Enter が見えて、Enter から本文へ進みたい。COMPLETE! にならず LOADING のまま残るのは受け入れる
21. 閲覧者として、トップの最大の描画 (LCP) が遅くならないでほしい。キャラクターは今と同じく、最初から薄くぼけて見えていてほしい
22. スマートフォンの閲覧者として、カード・名前・Portfolio・状態の文字・バー・Enter が画面に収まってほしい。縦に短い画面でも欠けないようにするため
23. 持ち主として、導入演出の色とガラスの質感を、今と同じトークンとユーティリティで管理したい

## Implementation Decisions

- **導入演出の状態**: 導入演出の進み具合は、React から切り離した純粋な関数で決める (いまの引き継ぎの判断を作り替える。「引き継ぎ」の名を持たない関数とファイルにする)
  - 出来事は「導入演出が終わった」「待ちの上限 (演出の終わりから 8 秒) を過ぎた」「入口が押された」の 3 つ。背景の準備完了は、出来事ではなくストアから毎回受け取る
  - 状態は「演出中」「背景待ち」「完了」「打ち切り」の 4 つ。いまの「引き継ぎ済み」と「あきらめ」は、見た目が同じになるので「完了」にまとめる
  - 上から順に当てはめる: 入口が押された → 打ち切り / 描いた時点で準備完了が済んでいた (サイト内の移動で戻った) → 完了 / 演出が終わっていない → 演出中 / 準備完了か待ちの上限 → 完了 / それ以外 → 背景待ち
  - 完了と打ち切りは、その後の出来事で変わらない。準備完了と演出の終わりは、どちらが先でも完了になる
- **トップでの 3D 背景**: トップでは 3D 背景に切り替えない。導入演出の層は完了のあとも消さずに残し、3D 背景はその下で読み込み・描画を続ける (いまと同じ負荷)。引き継ぎで層を薄くする処理と、見出しをふわっと見せる処理は無くす
- **見出し**: 別に置いていた見出しの要素を無くす。最後のコマの名前と「Portfolio」を本物の h1 にする
  - HTML の中の文字は「Ryuki Tobita」「Portfolio」と書き、大文字は CSS で見せる。名前は 1 文字ずつ分けて浮かばせる (いまと同じ)
  - 隠した文字 (画面に出さない見出し) は持たない
  - 見出しは導入演出の層の中にあるが、飾りとして読み上げから外さない。見出しの名前は「Ryuki Tobita Portfolio」になる
  - 名前と「Portfolio」は縦に並ぶ別の要素なので、境目の空白はテキストに残らない。画面に出ない空白を 1 つ置き、文字としては「Ryuki Tobita Portfolio」にする。見た目の並びは変えない
  - いま 1 行の「PORTFOLIO · LOADING」は、「PORTFOLIO」(見出しの一部) と、状態の文字 (見出しの外) に分ける
- **状態の文字と完了の見せ方**: 状態の文字は「LOADING」と「COMPLETE!」で、言語に依らない英字の飾り (読み上げない)。完了で LOADING から COMPLETE! に替わり、そのときに一度光る (いまの「最後に一度光る」を、5 秒の時点から完了の時点へ移す)
  - バーは 5 秒で 9 割まで満ち、残りの 1 割を完了で満たす
  - 背景待ちのあいだは、最後の姿のまま数秒おきにゆっくり瞬きする (いまと同じ)。完了のあとは目を開けたまま止める
- **入口**: 演出の最初から押せるリンクのまま。押したら導入演出を打ち切り、/overview へ移る
  - 完了で、縁の光をゆっくり脈打たせて少し目立たせる
  - 視差効果を減らす設定では脈打たせず、縁の光を強めるだけにする
- **演出を流さないとき**: 次の場合は演出を流さず、最後の姿をいきなり出す
  - サイト内の移動でトップに戻ったとき: 描いた時点で背景の準備完了が済んでいるので、最初から完了 (光らない)
  - 入口で打ち切ったあと: 打ち切りも完了の姿 (COMPLETE!・満ちたバー・目を開けた姿) として、演出を止める。Next.js (Cache Components) は移った先から戻るとき、前のページを部品の状態ごと見せ直す (React の Activity)。そのとき CSS のアニメーションは頭から流れ直すので、止めておかないと、戻ったときに演出がもう一度流れてしまう
  - 視差効果を減らす設定のとき: 開いた瞬間に導入演出が終わったとみなす (いまの 1 秒の時計は無くす)。そのうえで準備完了か待ちの上限 (8 秒) を待ち、動きなしで COMPLETE! に替わる
  - 最初の HTML には常に導入演出を含める (いまと同じ。サーバーでは準備完了にならないので、ハイドレーションと食い違わない)
- **読み上げ**: 導入演出の領域の名前は、演出中と背景待ちでは「読み込み中」、完了では「読み込み完了」(英語版 "Loaded") にする
  - トップの殻は言語を読めないので、言語の島が両方の文言を隠した要素として描き、導入演出の部品は状態に合わせて aria-labelledby の指す先を切り替える
  - 完了の時点で読み上げを割り込ませること (aria-live) はしない
  - 「読み込み完了」は画面の固定の文言 (日本語が正本、英語版も用意) に足す
- **JS を切ったとき**: CSS のアニメーションで最後のコマまでは進むが、完了を知る手段がないので LOADING のまま残る。見出しと Enter が見えて押せることだけを守る
- **記録**: ADR 0034 に、日付つきの追記で「見出しを見せる段と 3D 背景への引き継ぎをやめ、完了で止める」と書く。intro-handoff.md の冒頭に、この仕様で改めたことを書く

## Testing Decisions

- よいテストとは、閲覧者から見える振る舞い (何が見え、何が押せ、どこへ移るか、領域と見出しの名前) と、導入演出の状態の判断の結果だけを確かめるもの。CSS のアニメーションの途中のコマや、光る・脈打つ動きそのものには依らない
- **合意済みの seam**
  1. **トップの E2E** (一番外側)
     - トップを開くと導入演出が出る (領域の名前「読み込み中」で取る)
     - 入口が最初から押せて、押すと /overview に移る
     - 演出のあと、領域の名前が「読み込み完了」に替わる。層は残ったままで、h1「Ryuki Tobita Portfolio」と Enter が見える (最大 15 秒待つ)
     - 視差効果を減らす設定でも完了になる
     - サイト内の移動でトップに戻ったときは、最初から「読み込み完了」で出る
     - トップ以外のページに直接入ったときは導入演出が出ない (いまのまま)
     - 入口に `glass-button` が当たっている (いまのまま)
     - JS を切っても、h1「Ryuki Tobita Portfolio」と Enter が見える
     - 視差効果を減らす設定では、名前の文字に動きが付かない
     - 英語に切り替えたときは、領域の名前が英語で出る (いまのまま)
  2. **導入演出の状態の判断** (Vitest のユニット): 3 つの出来事と背景の準備完了の、あらゆる順番で状態が正しく決まること
     - 演出の終わりと準備完了は、どちらが先でも完了になる
     - 演出の終わりから待ちの上限を過ぎると、準備完了が無くても完了になる
     - 演出の終わりより前に待ちの上限の出来事が来ても、完了にはならない (上限は演出の終わりから数える)
     - 描いた時点で準備完了が済んでいれば、最初から完了
     - 入口が押されたら打ち切り。完了と打ち切りは変わらない
- 先例
  - E2E: e2e/intro.spec.ts (導入演出と視差効果を減らす設定)、e2e/home.spec.ts (JS なしの見出しとリンク)、e2e/i18n.spec.ts (英語の領域の名前)
  - ユニット: いまの引き継ぎの判断のユニットテスト (出来事の順番を並べて状態を確かめる)
- 外部の LLM や Slack は関わらない
- E2E は `e2e/fixtures.ts` の `test` / `expect` を使い、観点タグと対象ルートを付ける。動きを確かめる describe だけ reducedMotion を no-preference に戻す (いまの方針のまま)

## Out of Scope

- トップにいるあいだ、見えない 3D 背景の描画を止めること (別の PBI の候補。いまも演出の下で描いているので、新しい負荷ではない)
- トップで 3D 背景の上に導入演出のカードを重ねる見た目 (案 a。今回は採らない)
- 導入演出の 5 秒の流れそのもの (破片・キャラクター・名前の浮かび方) の作り替え
- JS を切ったときに COMPLETE! を出すこと
- 完了を読み上げで知らせること (aria-live)

## Further Notes

- 持ち主の提案 (2026-10-24): 「最後のコマを Complete! にして Enter でトップページへ進めばよい。見出しの表示は飛ばしてよい。ただし SEO のため文字列は裏で持ちたい」。この「裏で持つ」は、隠した文字ではなく、画面に見えている名前を本物の h1 にすることで満たす、と合意した
- 背景の準備完了は、トップでは「COMPLETE! を出す合図」と「/overview に入ったときに 3D 背景がもう描ける状態」の両方の意味を持つ
- ADR 0034 の「3D 背景の遅延読み込み」「背景の準備完了の知らせ」「LCP のためにキャラクターを薄くぼかして出す」は変えない
