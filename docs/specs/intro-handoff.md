# トップの導入演出と、3D 背景への引き継ぎ

## Problem Statement

トップを開いたとき、3D 背景の読み込み (three.js の読み込みとシェーダーのコンパイル) が終わるまで時間がかかる。その間はブラウザの手がふさがり、「Enter」を押しても反応が遅れることがある。読み込み中の画面には何も起きず、閲覧者には「重いサイト」に見える。
持ち主は、読み込みの時間をただ待たせるのではなく、自分のキャラクターを使ったスタイリッシュな演出で埋め、そのあいだも入口はすぐ押せるようにしたい。

## Solution

トップを読み込んだときにだけ、3D 背景の代わりに、5 秒ほどのガラス調の導入演出を背景に流す。導入演出では、ガラスの破片が 1 枚のカードに集まり、ガラスの奥でキャラクターが目を開けてゆっくり瞬きし、名前が浮かび、進み具合のバーが満ちる。
3D 背景は、ページが操作できる状態になってから裏で読み込む。導入演出が終わり、かつ背景の準備完了になったら、約 1 秒かけて導入演出を薄く消しながら 3D 背景を浮かび上がらせる (引き継ぎ)。
見出し「Ryuki Tobita Portfolio」は、導入演出のあいだは透明のまま置いておき、引き継ぎのあとにふわっと見せる。入口はガラス調のボタンにして、画面の下寄りの中央に置き、導入演出の最初から押せるようにする。

## User Stories

1. 閲覧者として、トップを開いたらすぐに何かが動き始めてほしい。待たされている感じを受けないようにするため
2. 閲覧者として、導入演出の最中でも入口を押して本文へ進みたい。演出を見たくないときに待たなくて済むようにするため
3. 閲覧者として、入口を押したらすぐに反応してほしい。サイトが固まっていると感じないようにするため
4. 閲覧者として、導入演出の途中で入口を押したら、演出が打ち切られて本文へ移ってほしい。演出の終わりを待たなくて済むようにするため
5. 閲覧者として、導入演出が終わったら、途切れずに 3D 背景へ移ってほしい。画面が一瞬真っ暗になったり、ちらついたりしないようにするため
6. 閲覧者として、回線が遅くて 3D 背景の準備が間に合わないときは、導入演出の最後の姿のまま (ときどき瞬きをしながら) 待ちたい。何も表示されない時間ができないようにするため
7. WebGL が使えない端末の閲覧者として、3D 背景が出なくても、導入演出の最後の姿を背景としてトップを使いたい。壊れた画面にならないようにするため
8. 閲覧者として、引き継ぎのあとに「Ryuki Tobita Portfolio」の見出しを読みたい。何のサイトかが分かるようにするため
9. 閲覧者として、背景の準備完了にならないまま待ち続けても、導入演出が終わって 8 秒たったら見出しを読みたい。見出しが透明のまま残らないようにするため
10. 閲覧者として、サイト内を移動してトップに戻ったときは、導入演出をもう一度見せられたくない。同じ演出を何度も待たされないようにするため
11. 閲覧者として、トップ以外のページから直接サイトに入ったときは、導入演出なしで 3D 背景を見たい。読みたいページにすぐ入れるようにするため
12. 閲覧者として、導入演出の途中で言語を切り替えても、演出を最初からやり直されたくない。切り替えのたびに待たされないようにするため
13. 視差効果を減らす設定にしている閲覧者として、動く演出を見せられたくない。目を開けたカード 1 枚を短く見せたあと、止まった 3D 背景に移ってほしい
14. スクリーンリーダーの利用者として、導入演出の飾りの文字 (英字の名前・「PORTFOLIO · LOADING」) を読み上げられたくない。かわりに、表示言語に合わせた「読み込み中」を知りたい
15. スクリーンリーダーの利用者として、見出しと入口は導入演出の最中から読み上げられてほしい。見た目で透明でも、ページの中身が分かるようにするため
16. 検索エンジンやリンクのプレビューとして、見出しと入口が最初の HTML に含まれていてほしい。JS を動かさなくてもページの中身が分かるようにするため
17. 閲覧者として、トップの最大の描画 (LCP) が遅くならないでほしい。キャラクターが最初から薄くぼけて見えていて、だんだんはっきりしてほしい
18. 閲覧者として、トップ以外のページでも、3D 背景の読み込みでボタンの反応が遅れないでほしい。どのページも操作しやすくするため
19. 閲覧者として、入口にマウスを乗せたら、ガラスに光の帯が走るなどの反応がほしい。押せるものだと分かるようにするため
20. スマートフォンの閲覧者として、導入演出のカード・名前・バー・入口が画面に収まってほしい。縦に短い画面でも欠けないようにするため
21. 持ち主として、導入演出の色をサイトのトークンとして管理したい。決まり (生の色を書かない) を守り、後から調整しやすくするため
22. 持ち主として、入口のガラスの見た目を共通のユーティリティにしたい。ほかのボタンでも同じ質感を使えるようにするため
23. 持ち主として、導入演出のキャラクターの絵を軽く保ちたい。最初の表示を重くしないため

## Implementation Decisions

- **導入演出の部品** (トップの機能の部品として新しく作る): CSS のアニメーションだけで動かす。JS は、名前を 1 文字ずつ分けることと、引き継ぎの判断に要る出来事 (導入演出の終わり) を知らせることだけに使う。演出の流れは、試作 (5 秒、1920×1080 で確認済み) と同じにする
  - ガラスの破片が集まる (0〜1.3 秒)
  - キャラクターがガラスの奥でぼけた状態から、ピンクと水色にずれた像を重ねてくっきりする (〜2.3 秒)
  - 前面のすりガラスの板が上がる (〜2.5 秒)
  - 目を開ける (2.4 秒から 0.35 秒)
  - 光の帯が 2 回横切る
  - ゆっくり瞬きする (3.5 秒から 0.7 秒)
  - 名前が 1 文字ずつ浮かぶ
  - バーが満ちる
  - 最後に一度光る
- **キャラクターの絵**: 目を開けた絵と目を閉じた絵の 2 枚 (白い背景を抜いた webp、各 90KB 前後) を重ね、透明度で切り替える。目を閉じた絵を先に読み込む
- **LCP**: キャラクターは最初から、薄く強くぼかした状態で出しておき (透明度 0 にしない)、だんだんはっきりさせる
- **待つあいだ**: 導入演出が終わっても背景の準備完了になっていなければ、最後の姿のまま、数秒おきにゆっくり瞬きを繰り返す。進み具合の数字は出さず、バーは飾りとして 5 秒で満ちる
- **引き継ぎの判断** (純粋な関数として切り出す): 出来事は「導入演出が終わった」「背景の準備完了」「導入演出が終わってから 8 秒たった」「入口が押された」の 4 つ。状態は「演出中」「背景待ち」「引き継ぎ済み」「あきらめ」の 4 つ。順番に関係なく、導入演出の終わりと背景の準備完了がそろったら引き継ぎ済みになる。あきらめでは、導入演出の最後の姿を残して見出しを見せる。引き継ぎ済みとあきらめは、その後の出来事で変わらない
- **背景の準備完了の知らせ**: 3D 背景は、最初の 1 枚を描き終えたことを、背景テーマの選択と同じ形の小さなストア (購読と取得) で知らせる。導入演出はそれを購読する
- **3D 背景の読み込みの時刻**: 全ページで、ハイドレーションのあとブラウザの手が空いたときに three を読み込み始める。トップでは、背景は導入演出の下で透明のまま読み込み・描画を進め、引き継ぎで見えるようにする
- **導入演出を流すかどうか**: トップを描くときに、背景の準備完了がすでに来ていれば (サイト内の移動で戻った) 導入演出を出さない。サーバーで描く最初の HTML には常に導入演出を含める (サーバーでは準備完了にならないので、ハイドレーションと食い違わない)。言語の切り替えによる再描画では、導入演出の部品は描き直されないので、流れ直さない
- **入口**: 押したら導入演出を打ち切り、/overview へ移る。押せることは導入演出に依らない (トップの HTML に最初からあるリンク)
- **トップのページ**: サーバーコンポーネントのままにする。見出しは透明度 0 で置き、引き継ぎ (またはあきらめ) のあとに見せる。見た目の切り替えに要る状態だけを、小さなクライアントの部品に閉じ込める
- **色**: 導入演出のピンク・水色・紫・赤を、演出用の色のトークンとして足す。3D 背景のテーマのような例外にはしない
- **ガラス調のボタン**: 共通のユーティリティ `glass-button` として足す (すりガラスの面・縁の光・ホバーで光の帯が横切る)
- **視差効果を減らす設定**: 導入演出のアニメーションを止め、目を開けたカードを 1 秒ほど見せたら導入演出が終わったとみなす。3D 背景は止まった 1 枚 (既存の振る舞い) で引き継ぐ
- **文言**: 導入演出の英字 (名前・「PORTFOLIO · LOADING」) は飾りとして読み上げから外す。読み上げ用の「読み込み中」は、画面の固定の文言 (日本語が正本、英語版も用意) に足す
- **記録**: 新しい ADR (0034) に、導入演出・three の遅延読み込み・引き継ぎの判断を書き、ADR 0012 から参照する。ADR 0004 と theme.md に、演出用の色のトークンと `glass-button` を足す

## Testing Decisions

- よいテストとは、閲覧者から見える振る舞い (何が見え、何が押せ、どこへ移るか) と、引き継ぎの判断の結果だけを確かめるもの。CSS のアニメーションの途中のコマや、内部の状態の持ち方には依らない
- **合意済みの seam**
  1. **トップの E2E** (一番外側)
     - トップを開くと導入演出が出る (読み上げ用の「読み込み中」で取る)
     - 入口が最初から押せて、押すと /overview に移る
     - 演出が終わると 3D 背景の canvas が見え、導入演出が消え、見出しが不透明になる (最大 15 秒待つ。この流れを確かめるテストは 1 本だけ)
     - 視差効果を減らす設定でも引き継ぎが起きる
     - サイト内の移動でトップに戻ったときは導入演出が出ない
     - トップ以外のページに直接入ったときは導入演出が出ない
     - `glass-button` と演出用の色のトークンが当たっている (トークンと computed style で確かめる)
  2. **引き継ぎの判断** (Vitest のユニット): 4 つの出来事のあらゆる順番で、状態が正しく決まること
     - 導入演出の終わりと準備完了は、どちらが先でも引き継ぎ済みになる
     - 8 秒たつとあきらめになる
     - 引き継ぎ済みとあきらめは変わらない
     - 入口が押されたら打ち切る
- 先例
  - E2E: 背景テーマの E2E (canvas と `data-background-theme`、視差効果を減らす設定)、トップの E2E (JS なしで見出しとリンクが出る、視差効果を減らす設定で演出が付かない)、テーマの E2E (トークンと computed style)
  - ユニット: 背景の間引きの判定のユニットテスト (純粋な関数を時刻の列で確かめる)
- 外部の LLM や Slack は関わらない
- E2E は `e2e/fixtures.ts` の `test` / `expect` を使い、観点タグと対象ルートを付ける

## Out of Scope

- トップ以外のページでの導入演出
- 導入演出の動画ファイル (mp4) をサイトで流すこと。確認用の mp4 は作ったが、サイトでは CSS で動かす
- 3D 背景のシェーダーのコンパイルを別スレッドに移すこと (OffscreenCanvas など)
- 導入演出の中身の差し替えや、季節ごとの演出
- 全ページの静的化 (PBI-0026 で扱う)

## Further Notes

- 試作 (単一の HTML と、時刻を止めて 1 コマずつ撮った確認用の mp4) は、持ち主と見た目を合意済み。実装はこの試作の見た目とタイミングに合わせる
- three の準備の途中 (シェーダーのコンパイル) では、ブラウザが一瞬固まる。導入演出のうち透明度と位置の動きは止まらないが、ぼかしの動きはその瞬間だけカクつくことがある。持ち主はこれを受け入れている
- この作業は、トップをサーバーで描く変更 (PBI-0025、マージ済み) の上に乗る
