# /now の記事の英語版

- 日付: 2026-10-24
- 状態: 合意済み (design-flow の grilling で持ち主と確認)
- 用語: [CONTEXT.md](../../CONTEXT.md) の「記事」「記事の画像」「英語版」「持ち主」
- 関連: [ADR 0037](../adr/0037-now-post-english-auto-translation.md)、[ADR 0026](../adr/0026-locale-cookie-and-dictionaries.md)、[ADR 0015](../adr/0015-now-posts-storage-and-markdown.md)、[ADR 0031](../adr/0031-now-post-images.md)、[ADR 0035](../adr/0035-cache-components-and-prefetch.md)、[ADR 0018](../adr/0018-slack-notify-decorator.md)

## Problem Statement

サイトは右上のスイッチで英語に切り替えられる (ADR 0026) が、/now の記事だけは日本語のまま出る。英語のときはページの下に「Posts are written in Japanese.」と一律に出すだけで、英語で読みたい閲覧者 (海外の採用担当や発注者) は記事の中身を読めない。
持ち主は記事を日本語で書いて Postman から投稿している。投稿のたびに英語版を自分で書いて送るのは手間が大きく、続かない。

## Solution

記事を投稿・書き換えると、サイトが LLM (Kimi) で**英語版**を自動で作り、記事と一緒に保存する。訳は応答を返したあとに作るので、投稿の応答は遅くならない。
表示言語が英語のとき、一覧のカードと記事のページは英語版の題名と本文を出す。英語版が無い記事 (訳す前・訳に失敗した・今ある記事) は日本語のまま出し、日本語であることを断る。
自動訳には「Machine-translated from Japanese.」と添える。訳が気に入らなければ、持ち主は自分で書いた英語版 (持ち主の訳) を送って置き換えられる。今ある記事や、訳に失敗した記事は、訳し直しの API で 1 件ずつ英語版を作れる。
RSS・Slack の知らせ・検索エンジン (Cookie を持たない) には今までどおり日本語を出す。

## User Stories

1. 英語で閲覧する人として、/now の記事を英語で読みたい。持ち主がいま何に取り組んでいるかを知るため
2. 英語で閲覧する人として、一覧のカードの題名と抜粋も英語で見たい。どの記事を開くか選べるようにするため
3. 英語で閲覧する人として、記事のページの題名・本文・日付まわりを英語で見たい
4. 英語で閲覧する人として、英語版の無い記事は日本語であると分かるようにしてほしい。表示の不具合と取り違えないため
5. 英語で閲覧する人として、自動で訳された記事はそうと分かるようにしてほしい。訳のぎこちなさを持ち主の英語力と取り違えないため
6. 英語で閲覧する人として、記事の画像と図は日本語版と同じものを見たい
7. 英語で閲覧する人として、画像の代替テキストも英語で読みたい (読み上げソフトを使うときも)
8. 読み上げソフトを使う人として、日本語のまま出る記事は日本語として読み上げてほしい
9. 日本語で閲覧する人として、今までと同じ日本語の記事を見たい (英語版の有無で表示が変わらない)
10. 持ち主として、記事を日本語で投稿するだけで英語版ができてほしい。英語版を自分で書く手間をなくすため
11. 持ち主として、英語版を作るせいで投稿の応答が遅くならないでほしい
12. 持ち主として、日本語を書き換えたら英語版も新しい日本語から作り直してほしい。古い英語版を出し続けないため
13. 持ち主として、公開日だけを変えたときは英語版を作り直さないでほしい。LLM の呼び出しを無駄にしないため
14. 持ち主として、自動訳が気に入らないとき、自分で書いた英語版で置き換えたい
15. 持ち主として、自分の英語版を Postman で .md のファイルとして送りたい。記事の投稿と同じ手順で済ませるため
16. 持ち主として、英語版を消して日本語だけに戻したい
17. 持ち主として、自動訳をすぐに作り直し、その結果をその場で確かめたい
18. 持ち主として、今ある記事にも英語版を付けたい
19. 持ち主として、自動訳に失敗したら Slack で知りたい。英語版が無いままになっていることに気付くため
20. 持ち主として、訳のせいで図 (Mermaid) やコードが壊れないでほしい
21. 持ち主として、訳のせいで画像の参照が外れないでほしい
22. 持ち主として、自分の英語版がその記事に無い画像を参照していたら、送った時点で断ってほしい
23. 持ち主として、訳している間に記事を書き換えたり消したりしても、古い訳で上書きされないでほしい
24. 持ち主として、自分の英語版を送ったあとに、先に始まっていた自動訳で上書きされないでほしい
25. 持ち主として、RSS は今までどおり日本語で配りたい
26. 開発者として、手元・E2E・CI では本物の LLM を呼ばずに動かしたい (API キーが無ければ訳さない)

## Implementation Decisions

### 記事のデータ

- 記事に任意の項目 `en` (英語版) を足す。英語版の無い記事は今までと同じ形のまま。保存先・キーは変えない (Redis のハッシュ `now:posts` の同じ値に入る)
  - `title`: 英語の題名
  - `body`: 英語の本文 (Markdown)。画像は日本語版と同じファイル名で参照し、記事の画像の対応表を共有する
  - `source`: `"auto"` (自動訳) か `"owner"` (持ち主の訳)
  - `updatedAt`: 英語版を保存した日時 (ISO 8601、UTC)
- 保存先から読むときの検証 (壊れた値の記事を捨てる) に `en` を含める。`en` だけが壊れているときは記事を捨てず、`en` を外して読む

### 自動訳の部品

- 入力は日本語の題名と本文、出力は英語版の題名と本文か、失敗 (理由つき)。呼び出しは `apiFetch` を通す (ADR 0017)
- LLM はチャットと同じ Moonshot (Kimi)。API キー・ベース URL・モデルはチャットと同じ環境変数を使う。題名と本文を 1 回の呼び出しで訳し、JSON で受け取る
- 訳す: 題名、本文の文章、画像の代替テキスト。訳さない: コードブロック (` ```mermaid ` の図も含む)、インラインコード、画像のパス、リンクの URL
- 訳したあとに検査し、通らなければ失敗にする
  - 画像の参照 (パス) の並びが元と同じ
  - コードブロックの数・順・中身が元と同じ
  - 題名と本文が空でなく、記事の上限 (題名 120 字・本文 20000 字) に収まる
- API キーが無ければ「設定されていない」を返す (呼び出し側はそれを見て訳さずに飛ばす)
- 時間の上限を付け、関数の上限 (300 秒) より手前で打ち切る

### 投稿と書き換え (今ある `POST /api/now`・`PUT /api/now/[id]`)

- 受け取る形と応答は変えない。応答は英語版を含まない (訳は応答のあとにできる)
- 投稿: 記事を保存したあと、`after()` で自動訳を作る
- 書き換え: 日本語の題名か本文が変わったときは、保存する記事から英語版を外し (古い英語版を出さない)、`after()` で自動訳を作り直す。題名も本文も変わらなければ、英語版はそのまま残し、訳し直さない
- `after()` の中の手順: 自動訳を作る → 記事を読み直す → 次のどれかなら捨てる → 英語版を付けて保存 → 作り置きを捨てる (`revalidateTag`、ADR 0035)
  - 記事が消えている
  - 日本語の題名か本文が、訳したものと違う
  - 英語版が、訳し始めたときから変わっている (その間に持ち主の訳が送られた・別の訳が保存された)
- 自動訳が失敗したら、記事はそのまま (英語版なし) にし、`SLACK_WEBHOOK_URL` があれば Slack に「記事 ○○ の英語版を作れませんでした」と理由つきで知らせる (`notifySlack`、ADR 0018。中身は /now の通知の組み立てに足す)。API キーが無いときは知らせずに飛ばす
- 書き込みの API (`/api/now` の下すべて) に `maxDuration = 300` を付ける

### 英語版の API (新しく足す。認証は `NOW_POST_TOKEN`、`withErrorHandling` → `withBearerAuth` で包む)

- `PUT /api/now/[id]/en`: 持ち主の訳を保存する
  - 受け方は記事の投稿と同じ: JSON の `{ title, body }`、または multipart の `file` (Markdown のファイル) と任意の `title`。題名を省いたらファイル先頭の `# 見出し`、無ければファイル名 (今の投稿と同じ決め方)。`publishedAt` と `images` は受けない
  - 本文が参照する画像は、その記事の画像の対応表に今あるものだけ。無い画像を参照していたら 400 (`details.issues` に何が悪いかを入れる)。外部の画像・代替テキストの無い画像も、記事の投稿と同じく 400
  - 成功したら `source: "owner"` で保存し、作り置きを捨て、記事全体を 200 で返す。記事が無ければ 404
- `DELETE /api/now/[id]/en`: 英語版を外して保存する。204。記事が無ければ 404、英語版が無くても 204
- `POST /api/now/[id]/en/translate`: 自動訳を今すぐ作り、終わるまで待つ
  - 成功したら `source: "auto"` で保存し (持ち主の訳があっても置き換える)、記事全体を 200 で返す
  - 訳に失敗したら 502 と理由。API キーが無ければ 503。記事が無ければ 404
  - 訳し終えたら記事を読み直し、`after()` と同じ判定で古いかを確かめる。訳の間に記事が消えていたら 404、日本語か英語版が変わっていたら 409 で、どちらも保存しない (ユーザーストーリー 23・24)
  - Slack には知らせない (結果を応答で返すため)

### 表示 (表示言語が英語のとき)

- 記事と表示言語から、出すものを決める純粋な関数を 1 つ置き、カード・記事のページ・metadata・JSON-LD がすべてこれを通す
  - 出力: 題名、本文、内容の言語 (`ja` / `en`)、断り書きの種類 (自動訳 / 日本語のみ / なし)
  - 日本語のとき: いつも日本語、断り書きなし
  - 英語で英語版があるとき: 英語版。`source` が `"auto"` なら断り書きは「自動訳」
  - 英語で英語版が無いとき: 日本語、内容の言語は `ja`、断り書きは「日本語のみ」
- 一覧のカード: 題名と抜粋を上の関数の結果から作る。日本語のみのカードは、題名と抜粋を `lang="ja"` で包み、短い印 (英語: "In Japanese") を添える
- 記事のページ: 題名・本文を上の関数の結果で出す。日本語のみの記事は本文を `lang="ja"` で包み、日付の下に「This post is available in Japanese only.」を出す。自動訳の記事は日付の横に「Machine-translated from Japanese.」を出す
- metadata (題名・説明) と JSON-LD (`headline`・`description`・`inLanguage`) も上の関数の結果から作る
- 一覧のページ下の一律の断り書き (`languageNote`) は消す
- 文言は `data/messages/ja.ts` と `en.ts` に足す (日本語のときは出ないが、型をそろえるため ja にも置く)
- 作り置き (`"use cache"`) が持つのは記事のデータのままにし、言語ごとの出し分けは作り置きの外 (上の関数) で行う。作り置きの鍵は増やさない

### 変えないもの

- RSS (`/rss.xml`): 日本語のまま、`<language>ja</language>`
- Slack の投稿・更新の知らせ: 日本語のまま
- 記事の URL、sitemap、canonical (英語版は検索に載せない。ADR 0026)
- proxy (記事の 404・旧リンクの 308)

## Testing Decisions

良いテストは外から見える振る舞いだけを確かめる。LLM の呼び出しの中身 (プロンプトの文言) や、保存の内部の手順は確かめない。**本物の LLM と本物の Slack は呼ばない** (`fetch` をモックする。`after()` は `vi.mock("next/server", ...)` で差し替える)。

合意済みの seam (テストを書く境界):

1. **/now の API の Route Handler** (既存の `test/app/api/now/` と同じ形。保存先はメモリ、Kimi と Slack の `fetch` と `after()` をモック)
   - 投稿で、応答のあとに自動訳が保存され、`source: "auto"` になる
   - 書き換えで、日本語が変わると英語版が外れて作り直され、変わらなければ英語版が残り LLM を呼ばない
   - API キーが無いと、訳さず、Slack にも知らせない
   - 自動訳が失敗すると、英語版なしのまま、Slack に知らせる
   - 訳している間に日本語が変わった・記事が消えた・持ち主の訳が送られたときは、訳を保存しない
   - `PUT /en` (JSON と multipart)、知らない画像を参照したときの 400、`DELETE /en`、`POST /en/translate` の 200・502・503・404、認証が無いときの 401
2. **自動訳の部品** (`fetch` をモック)
   - 日本語の題名と本文から英語版を返す
   - 画像の参照を落とした・コードブロックを書き換えた・空の訳を、失敗として返す
   - LLM の誤り・時間切れ・読めない応答を失敗として返す。API キーが無ければ「設定されていない」
3. **出すものを決める純粋な関数**
   - 日本語 / 英語 × 英語版なし / 自動訳 / 持ち主の訳 の組み合わせで、題名・本文・内容の言語・断り書きの種類
   - 自動訳の断り書きは、E2E では作れない (LLM を呼べない) ので、ここで確かめる
4. **E2E** (既存の `e2e/now.spec.ts`・`e2e/now-post-page.spec.ts` と同じ形。記事は `POST /api/now`、持ち主の訳は `PUT /api/now/[id]/en` で仕込む。webServer には API キーを渡さない)
   - Cookie を英語にすると、カードと記事のページ (題名・本文・`<title>`) に英語版が出る
   - 英語版の無い記事は、英語のときに日本語と「Japanese only」の断り書きで出る
   - 日本語のときは、英語版があっても日本語が出る
   - 期待する文言は `data/messages/` から import して突き合わせる

テストの前例: `test/app/api/now/route.test.ts` (Route Handler とメモリの保存先)、`test/lib/now/` (純粋な関数)、`test/app/api/chat/` (Kimi の `fetch` のモック)、`e2e/i18n.spec.ts` (Cookie で英語にする)。
`api-contract` 観点の対象に `/api/now/[id]/en` と `/api/now/[id]/en/translate` を足す (`pnpm test:coverage-map -- --check` で確かめる)。

## Out of Scope

- 英語版を検索エンジンに載せること (URL を言語で分ける、hreflang)。ADR 0026 のまま
- 英語の RSS フィード
- 図 (Mermaid) の中の文字や、文字入りの画像の英語版。図と画像は日本語版と共有する
- 英語版のための別の画像
- 今ある記事をまとめて訳す仕組み (スクリプト・一括の API)。持ち主が 1 件ずつ訳し直しの API を呼ぶ
- 日本語・英語以外の言語
- 自動訳の質を測る eval (チャットのプライバシー eval とは別物。システムプロンプトの変更には当たらないので `pnpm eval:privacy` は要らない)
- 持ち主の訳が日本語より古くなったことを知らせる仕組み (日本語を書き換えると自動訳で置き換わる)

## Further Notes

- `after()` の中で呼ぶ `revalidateTag` が作り置きを捨てられるかは、Next.js のドキュメントに書かれていない。捨てられなくても、作り置きの寿命は 5 分 (ADR 0035) なので、英語版は遅くとも 5 分で出る。持ち主が Vercel のプレビューで確かめ、WORK に結果を残す
- 自動訳の保存は「読み直す → 確かめる → 保存」で、Redis の上で不可分ではない。確かめてから保存するまでのごく短い間に書き換えが入ると、古い訳が残りうる。個人のサイトの書き込みの頻度では起きにくいので受け入れ、起きたら訳し直しの API で直す
- 検討の途中で「書き換えと同じリクエストで英語版も送れる」案が出たが、記事の API の受け方は変えないと決めたので採らない。持ち主の訳は書き換えのあとに `PUT /en` で送る (先に始まった自動訳は、英語版が変わっていれば保存しないので上書きされない)
- 関数の上限はプランと設定で決まる。`maxDuration = 300` がこのプロジェクトのプランで通るかは、デプロイ (プレビュー) で確かめる。上限を超えると `after()` の訳は打ち切られ、英語版なしのまま残る (Slack には知らせられない)
