# /now の記事の画像

- 日付: 2026-10-21
- 状態: 合意済み (design-flow の grilling で持ち主と確認)
- 用語: [CONTEXT.md](../../CONTEXT.md) の「記事」「記事の画像」「画像の組」「拡大表示」
- 関連: [ADR 0031](../adr/0031-now-post-images.md)、[PBI-0024](../pbi/0024-now-post-images/PBI.md)、[ADR 0015](../adr/0015-now-posts-storage-and-markdown.md)、[ADR 0024](../adr/0024-works-detail-data-and-diagrams.md)、[ADR 0030](../adr/0030-now-post-pages.md)

## Problem Statement

持ち主は、手元で書いた技術記事 (Markdown と、D2 で描いたライト用・ダーク用の SVG の図) を /now に載せたい。
ところが /now の記事は画像を扱わない決まり (ADR 0015) で、画像を置く場所も、記事と一緒に画像を送る方法も無い。
手元の記事は GitHub 向けに `<picture>` で図を入れているが、/now は生の HTML を描かないので、タグがそのまま文字で出てしまう。
一方で、今の描画は `![](https://どこでも)` を素の `<img>` で描いてしまい、外部の画像を止める仕組みも無い。
図は縦に長く、本文の幅では文字が読みにくいので、/works の図のように拡大して見たい。

## Solution

記事の投稿 (今ある `POST /api/now`・`PUT /api/now/[id]` の multipart) に、画像のファイルを何枚でも一緒に載せられるようにする。
本文には手元のファイルのまま相対パスで `![代替テキスト](assets/architecture-light.svg)` と書く。サーバーはファイル名で本文の画像と送られたファイルを結び付け、/now 専用の public の Vercel Blob ストアに置き、記事に「ファイル名 → 画像の URL・幅・高さ」の対応表を持たせる。
同じ .md が GitHub でもサイトでも表示できる (GitHub ではライト用が出る)。

ファイル名が `-light` で終わる画像と、同じ名前で `-dark` で終わる画像を一緒に送ると、2 枚は**画像の組**になり、サイトのテーマに合う方だけが表示される。
記事のページでは、画像は本文の幅に合わせて縮めて出し、押すと画面いっぱいの**拡大表示**が開く (/works の図と同じ部品)。
外部の画像、送られていない画像、代替テキストの無い画像、危ない SVG は、投稿の時点で 400 で断る。

## User Stories

1. 持ち主として、記事の .md と画像のファイルを 1 回のリクエストで投稿したい。画像を別の場所に上げてから URL を書き直す手間をなくすため
2. 持ち主として、Postman でファイルを選ぶだけで画像つきの記事を投稿したい。今の .md の投稿と同じ手順で済ませるため
3. 持ち主として、本文の画像は手元のファイルのままの相対パス (`assets/x.svg`) で書きたい。同じファイルを GitHub でもサイトでも表示できるようにするため
4. 持ち主として、本文の画像と送ったファイルをファイル名で結び付けてほしい。curl や Postman はフォルダを送らないため
5. 持ち主として、本文が参照しているのに送り忘れた画像があれば、どの名前が足りないかを 400 で知りたい。図の抜けた記事を公開しないため
6. 持ち主として、同じ名前のファイルを 2 つ送ったら 400 で知りたい。どちらが使われたか分からない状態を避けるため
7. 持ち主として、送ったのに本文のどこからも使われていないファイルがあれば 400 で知りたい。ファイル名や本文の打ち間違いに気づくため
8. 持ち主として、`x-light.svg` を本文に書き、`x-dark.svg` も一緒に送ったら、2 枚を組としてテーマで出し分けてほしい。ライト用・ダーク用の図を両方活かすため
9. 持ち主として、`-dark` を本文に書いていなくても、組になる `-dark` は「使われている」とみなしてほしい。未使用の 400 にならないようにするため
10. 持ち主として、組の片方しか無い画像は、その 1 枚をそのまま出してほしい
11. 持ち主として、代替テキストの無い画像は 400 で断ってほしい。読み上げで何の図か分からない記事を公開しないため
12. 持ち主として、本文に外部の画像 (`https://…`) を書いたら 400 で断ってほしい。外部のサーバーに閲覧者を追跡させたり、あとから画像を差し替えられたりしないため
13. 持ち主として、SVG・PNG・JPEG・WebP を載せたい。図と写真・スクリーンショットのどちらも使うため
14. 持ち主として、拡張子ではなく中身で形式を判定してほしい。拡張子を偽ったファイルを置かないため
15. 持ち主として、`<script>`・`on*` の属性・`<foreignObject>`・外部の URL の参照を含む SVG は 400 で断ってほしい。図を直接開かれたときにスクリプトが動く余地を残さないため
16. 持ち主として、D2 が出す SVG (`<style>` と、埋め込みの `data:` のフォント・画像を含む) は通ってほしい。手元の図をそのまま使うため
17. 持ち主として、1 枚 1MB・1 回 20 枚・リクエスト全体 4MB を超えたら、どの上限かが分かる 400 (全体は 413) で知りたい。Vercel の 4.5MB の上限で黙って失敗しないため
18. 持ち主として、投稿のレスポンスで、記事と一緒に画像の対応表 (名前・URL・幅・高さ) を見たい。置かれた画像を確かめるため
19. 持ち主として、誤字だけを直すときは、画像を送らずに PUT (JSON でも multipart でも) したい。直すたびに全部の画像を送り直さないため
20. 持ち主として、図を 1 枚差し替えるときは、その 1 枚だけを PUT で送りたい。残りは元の記事の画像を引き継いでほしい
21. 持ち主として、PUT で本文から外した画像は、記事の対応表からも外れ、Blob からも消えてほしい。使われない画像を溜めないため
22. 持ち主として、記事を DELETE したら、その記事の画像も Blob から消えてほしい
23. 持ち主として、Blob の画像を消すのに失敗しても、記事の更新や削除は成功のままにしてほしい。後始末の失敗で記事の操作がやり直しにならないため (消えなかった画像は表示に出ない)
24. 持ち主として、手元の開発サーバーで画像つきの記事を試しても、本物の Blob に書かないでほしい。試しの画像が公開のストアに残らないため
25. 持ち主として、本番で画像の置き場が設定されていないときは、画像つきの投稿だけを 503 にしてほしい。画像の無い投稿はこれまでどおり通すため
26. 閲覧者として、記事のページで図を本文の中で見たい
27. 閲覧者として、サイトのテーマに合う色の図だけを見たい。ライト用とダーク用が 2 枚並ばないようにするため
28. 閲覧者として、縦長の図も本文の幅に収まって表示されてほしい。横にはみ出さないようにするため
29. 閲覧者として、画像の読み込み中にも本文の位置がずれないでほしい (画像の幅と高さが分かっているので枠を先に取れる)
30. 閲覧者として、画像を押すと画面いっぱいの拡大表示を開き、倍率を変えて図の細部の文字を読みたい
31. 閲覧者として、拡大表示で、倍率を上げた図を縦横にスクロールして見回したい
32. 閲覧者として、拡大表示から元の画像を新しいタブで開きたい。ブラウザの拡大縮小や保存も使えるようにするため
33. キーボードだけで操作する閲覧者として、画像に Tab で移って Enter で拡大表示を開き、Esc で閉じたら画像にフォーカスが戻ってほしい
34. スクリーンリーダーを使う閲覧者として、画像の代替テキストと「拡大する」ボタンの名前を読み上げてほしい
35. 閲覧者として、画像の下の案内で、押すと拡大できることを知りたい
36. 英語で閲覧している閲覧者として、拡大表示のボタンや案内を英語で読みたい (記事の本文は日本語のまま)
37. 閲覧者として、記事のカードと RSS の抜粋に、画像の代替テキストが混ざらないでほしい。長い代替テキストが抜粋を埋めないようにするため
38. 閲覧者として、/works の図の拡大表示は、これまでどおりの見た目と動きで使いたい
39. 持ち主として、前から投稿してある記事 (画像の対応表が無い記事) も、これまでどおり表示されてほしい
40. 持ち主として、対応表に無い画像は `<img>` にならず、代替テキストの文字だけが出てほしい。外部の画像を描かないため

## Implementation Decisions

- **画像の置き場**: /now の画像専用に、Vercel Blob の **public** のストアを新しく作る。チャットの資料の private ストア (ADR 0019) とは分ける (アクセスの種類はストアごとに決まり、あとから変えられないため)。public の Blob はサイトと別のオリジンで、Vercel が CSP と `nosniff` を付けて配るので、SVG を直接開かれてもサイトのオリジンでスクリプトは動かない
  - サーバーが書き込みに使うトークンは専用の環境変数 `NOW_IMAGES_BLOB_READ_WRITE_TOKEN` だけを読み、SDK に明示して渡す (チャットの資料の `BLOB_STORE_ID` / `BLOB_READ_WRITE_TOKEN` と取り合わないため)
  - パスは `now/<記事 id>/<中身の SHA-256 の先頭 16 桁>-<ファイル名>`。中身が変われば URL も変わるので上書きは起きず、キャッシュは 1 年にする
  - サイトから Blob を読むことはない。ブラウザが Blob の URL を直接読む
- **画像の置き場の差し替え**: 記事の保存先 (ADR 0015) と同じ形で、画像の置き場を「置く」「消す (記事 id ごと・URL ごと)」の小さな面にする。実装は Blob とメモリの 2 つ
  - 選び方は記事の保存先と同じ条件: トークンがあれば Blob。無ければ、開発中と `NOW_POSTS_STORE=memory` (E2E) のときだけメモリ。メモリは画像の URL に `data:` URL を返す
  - 本番でトークンが無ければ、画像つきの投稿だけを 503 にする (画像の無い投稿は通す)
- **記事のデータ**: 記事に任意の `images` (画像の対応表) を足す。1 件は `name` (ファイル名)・`url`・`width`・`height`・`contentType`・`bytes`・`sha256`。前からある記事は `images` が無く、そのまま読める
  - 本文は送られたまま (相対パスのまま) 保存する。描くときに対応表で URL を引く
- **入力 (multipart)**: 今の `file` (Markdown)・`title`・`publishedAt` に、`images` 欄 (同じ名前で何度でも) を足す。JSON の入力は今までどおりで、画像は付けられない
  - 本文の画像の参照は、相対パスのファイル名 (最後の `/` より後ろ) で、送ったファイルのファイル名と結び付ける
  - 検査 (どれも 400、何が悪いかを `details` に入れる): 本文の画像に対応するファイルが無い / 同じファイル名が 2 つ / 使われていないファイル (使われている `-light` と組になる `-dark` は使われているとみなす) / 外部の画像 (`http:`・`https:`・`//`・`data:` など相対パス以外) / 代替テキストが空 / 形式が許されていない / 1 枚 1MB 超 / 21 枚以上
  - リクエスト全体が 4MB を超えたら 413 (Content-Length で先に見る)
  - ファイル名は英数字・`-`・`_`・`.` だけを許す (URL のパスにそのまま使うため)
- **画像の中身の検査**: 純関数の 1 モジュールにまとめる。入力はファイル名とバイト列、出力は「形式・幅・高さ」か「拒否の理由」
  - 形式は先頭のバイトで判定する (PNG・JPEG・WebP のシグネチャ、SVG は XML として `<svg` が根)。拡張子と形式が食い違えば拒否
  - 幅と高さ: PNG は IHDR、JPEG は SOF、WebP は VP8/VP8L/VP8X のヘッダ、SVG は `width`/`height` 属性、無ければ `viewBox`
  - SVG の拒否: `<script>`、`on` で始まる属性、`<foreignObject>`、外部を指す `href`/`xlink:href`/CSS の `url(...)`/`@import` (`#` で始まる内部の参照と `data:` は許す)。埋め込みの `data:image/svg+xml` も同じ検査を中までかける。中身を書き換えて無害にはしない (断るだけ)
- **画像の組**: ファイル名が `<基>-light.<拡張子>` の画像を本文が参照し、同じ投稿 (または引き継いだ表) に `<基>-dark.<拡張子>` があれば組にする。組でなければ 1 枚
- **PUT**: 新しい本文が参照する画像を、今回送ったファイル → 元の記事の対応表の順に探す。保存後の対応表には、新しい本文が参照する画像と、その組の `-dark` だけを残す。どちらにも無ければ 400
  - 画像を送らない PUT (JSON でも) は、元の対応表から引き継ぐ
- **後始末**: 記事の保存が成功したあとに、PUT で表から外れた画像を消す。DELETE では記事を消したあとに、その記事 id の画像をまとめて消す。消すのに失敗してもレスポンスは成功のままにし、サーバーのログに残す。定期的な掃除は作らない
- **POST の順序**: 検査をすべて済ませる → 画像を置く → 記事を保存する。記事の保存に失敗したら、置いた画像を消しにいく (失敗はログ)
- **レスポンス**: POST・PUT は今までの記事の形に `images` を足して返す
- **描画 (Markdown の部品)**: 部品に画像の対応表を渡せるようにする。対応表を渡さない呼び出し (/works の本文など) では、画像はすべて代替テキストの文字になる
  - 画像だけの段落は `<figure>` にする (`<p>` の中にブロックを入れないため)
  - 対応表にある画像は素の `<img>` に `width`・`height`・`loading="lazy"`・`decoding="async"` を付け、幅は本文いっぱいまで (`max-width: 100%`、高さは比率で決まる)。`images.unoptimized: true` なので next/image は使わない
  - 組なら 2 枚を `dark:hidden` と `hidden dark:block` で出し分ける (サイトのテーマは next-themes のクラスで決まる。ADR 0024 と同じ)
  - 対応表に無い画像は `<img>` にせず、代替テキストの文字だけを出す
- **拡大表示**: /works の `ArchitectureViewer` を、画像 1 枚 (または組) を受ける汎用の画像の拡大表示にして、共通の部品の層に移す。/works と /now の両方から使う (features 同士は import しない決まりのため)
  - /works の見た目と動きは変えない (倍率 5 段: 100・150・200・300・400%、全体表示に戻す、元の画像を新しいタブで開く、閉じたら開いたボタンにフォーカスを戻す)
  - 記事の画像はそれ自体を「拡大する」ボタンにし、下に「画像を押すと拡大して見られます」と添える。拡大表示の題は「<記事の題名> の画像」、代替テキストは読み上げ用の説明に入れる
  - 「元の画像を新しいタブで開く」は URL が `https:` のときだけ出す (開発中と E2E の `data:` URL はブラウザが新しいタブで開けないため)
  - Markdown の部品はサーバー部品のままにし、押せる画像と拡大表示はクライアント部品に切り出す (Mermaid の図と同じ)
  - 拡大表示の文言は ja/en の辞書の共通の場所に移す
- **抜粋**: カードと RSS の抜粋からは、画像を代替テキストごと落とす
- **RSS・構造化データ・OGP**: 変えない (今は平文の抜粋しか出していないため)
- **文書**: ADR 0031 で ADR 0015 の「画像は扱わない」の部分だけを置き換え、ADR 0015 にはそのことを 1 行足す。Markdown の部品の「画像の埋め込みは扱わない」のコメントも改める。AGENTS.md の構成の説明と環境変数の説明に、画像の置き場を足す

## Testing Decisions

- **良いテスト**: 外から見える振る舞い (HTTP のステータスとレスポンス、置き場に置かれた・消えた画像、画面に出るもの) だけを確かめる。内部の関数の呼ばれ方には依存しない。本物の Blob には書かない (メモリの置き場か、SDK のモックを使う)
- **合意済みの seam**:
  1. **API `POST /api/now`・`PUT /api/now/[id]`・`DELETE /api/now/[id]` を直接呼ぶユニットテスト (Vitest)**。画像の置き場はメモリのものを使う。確かめること: 画像つきの投稿で 201 と対応表が返り、置き場に画像がある / 足りない・重複・使われていない・外部の画像・代替テキストが空・形式違い・上限超えで 400 (全体の上限は 413) / PUT で送らなかった画像は元の表から引き継ぎ、外れた画像は置き場から消える / DELETE で画像も消える / 本番でトークンが無ければ画像つきだけ 503、画像の無い投稿は通る / 画像を消すのに失敗しても成功のレスポンス
  2. **画像の中身を調べる純関数のユニットテスト**。形式の判定、幅と高さの読み取り (4 形式)、拡張子との食い違い、SVG の危ないもの (script・on*・foreignObject・外部参照・入れ子の data:svg) の拒否。D2 が出す作りの SVG (`<style>`・埋め込みの `data:` フォント) が通ること
  3. **E2E (Playwright)**。`POST /api/now` で画像つきの記事を仕込む (既存の `/now` の E2E と同じやり方、題名は一意にする)。確かめること: 記事のページに画像が出る / テーマに合う方だけが見える / 押すと拡大表示が開き、倍率を変えられ、Esc で閉じると画像にフォーカスが戻る / アクセシビリティ (axe) の重大な違反が無い。/works の拡大表示の既存の E2E がそのまま通る
- Blob の置き場の実装 (SDK の呼び方) は、`@vercel/blob` をモックしたユニットテストで、パス・`access: "public"`・トークン・キャッシュの秒数・上書きしないことを確かめる (チャットの資料の Blob のテストと同じやり方)
- 抜粋は既存の抜粋のユニットテストに、画像が落ちることを足す
- **お手本**: API は `test/app/api/now/` の route のテスト (`helpers.ts` のリクエストの作り方、multipart の投稿のテスト)。Blob は `test/lib/chat/documents.test.ts`。E2E は `e2e/now-post-page.spec.ts` と、/works の拡大表示の E2E
- **観点の対応**: API は api-contract (必須)、記事のページは smoke (必須)・interaction・a11y。`pnpm test:coverage-map -- --check` で必須の観点に穴が無いことを確かめる

## Out of Scope

- `<picture>` や生の HTML の画像の受け付け (記事側を `![]()` に書き直す)
- 外部の画像の表示
- 画像の中身を書き換えて無害にすること (サニタイズ)。危ない SVG は断るだけ
- 画像の最適化 (srcset・形式の変換・リサイズ)
- 参照されなくなった画像の定期的な掃除 (Cron)
- ブラウザから直接 Blob に上げるクライアントアップロード (4.5MB を超える画像)
- サイト全体のセキュリティヘッダ (CSP の `img-src` など)。別の PBI にする
- RSS の全文配信・記事ごとの OGP 画像・構造化データの `image`
- 記事の画像の題 (キャプション) や大きさの指定の記法
