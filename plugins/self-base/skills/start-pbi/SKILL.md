PBI ありきで開発する。**PBI と WORK が無い実装には着手しない。**
リポジトリ固有の手順は `docs/agents/development-flow.md` にある。あればそれを正として従い、ここに書いた内容と食い違えばそちらを優先する。

## 手順

1. 既存の PBI を探す: `docs/pbi/` を見て、同じ目的の PBI があればそれを使う (WORK に追記する)
2. 無ければ新しく起こす
   - 番号は既存の最大 + 1 (4 桁)。フォルダは `docs/pbi/<番号>-<kebab-case の slug>/`
   - `docs/pbi/_template/PBI.md` と `WORK.md` をコピーする
3. `PBI.md` を書く (依頼者の言葉を要約し、推測は推測と書く)
   - 背景・目的 / やること / やらないこと / 受け入れ条件 (確かめられる形で) / 関連 ADR
   - 受け入れ条件には、それを確かめるテスト (E2E の観点・ユニット) を必ず対応させる
4. `WORK.md` に作業計画を書く
   - タスクを箇条書きにし、各タスクに「完了の確かめ方」を添える
   - 設計上の判断 (ライブラリの採用、構成の変更、方針ファイルの変更など) が要るなら「ADR が必要」と書き、`docs/adr/` に ADR を起こしてから実装する
5. 依頼が曖昧で受け入れ条件が書けないときは、ここで依頼者に確認する
6. 実装中は WORK.md の「記録」に、判断したこと・詰まったこと・方針を変えたことを日付付きで足していく
7. 終わったら受け入れ条件をすべて確かめ、PBI.md の状態を「完了」にする。PR は `create-pr` スキルで作る

## 書き方の約束

- 日本語で書く。理由 (なぜそうするか) を必ず書く
- 1 つの PBI は 1 つの PR で終わる大きさにする。大きければ PBI を分ける
- 秘密情報 (API キー・個人の連絡先) は書かない
